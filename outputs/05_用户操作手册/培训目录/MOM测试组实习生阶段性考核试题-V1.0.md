# MOM测试组实习生阶段性考核试题-V1.0

## 一、考核目标

- 检查实习生对 MOM 核心业务主线的理解程度。
- 检查实习生对基础术语、模块作用、上下游关系的掌握程度。
- 检查实习生是否能按“基础数据 -> 计划 -> 执行 -> 反馈”的主线在系统中完成基本操作。
- 检查实习生对 Jira 缺陷流转、故事点含义以及低代码平台核心能力的基本认知。

## 二、考核方式建议

- 总时长建议：`30-45 分钟`
- 口头问答：`20 分钟`
- 上机操作：`15-20 分钟`
- 追问与点评：`5 分钟`

## 三、题目结构与建议分值

| 模块 | 建议分值 | 说明 |
| --- | --- | --- |
| 业务术语与基础数据 | 25分 | 看是否理解核心对象和关系 |
| 计划与执行主线 | 30分 | 看是否理解订单、工艺路线、排程、执行反馈 |
| 角色权限与平台能力 | 15分 | 看是否理解权限配置和平台侧能力 |
| Jira 与缺陷流程 | 15分 | 看是否理解测试协作基本规范 |
| 上机操作 | 15分 | 看是否能实际操作并讲清楚步骤 |

## 四、口头问答题

### 4.1 业务术语与基础数据

1. 什么是 `工艺路线`？它在 MOM 里解决什么问题？
考官关注点：是否能说出“定义生产步骤/工序顺序/资源要求/工时依据”，并理解它会影响计划排程和任务生成。

2. 工艺路线一般在什么环节被使用？
考官关注点：是否能说出“生产订单指定工艺路线 -> 制造订单工艺展开 -> 制造任务/工序任务生成 -> APS 排程和现场执行”。

3. 什么是 `生产订单`？它和 `制造订单` 有什么区别？
考官关注点：是否理解生产订单偏计划域、制造订单偏车间执行域。

4. 生产订单页面通常可以做哪些核心操作？
考官关注点：查询、新增、导入、发布、齐套检查、订单释放、指定优先级/工艺路线/计划员/计划时间、暂停/恢复/取消。

5. 什么是 `工作中心`？它和 `设备` 的关系是什么？
考官关注点：是否理解工作中心是资源组织或能力归类，设备是更细粒度的实际资源。

6. 什么是 `BOM/MBOM`？它和工艺路线有什么区别？
考官关注点：`BOM` 关注“做什么、用什么物料”，工艺路线关注“怎么做、按什么工序做”。

7. 为什么 `基础数据` 会直接影响计划结果和执行结果？
考官关注点：是否理解物料、工艺路线、工作中心、日历、工时、权限配置不准会导致排程失真或执行失败。

### 4.2 APS、计划与执行主线

8. `RCCP`、`MRP`、`APS` 各自主要解决什么问题？
考官关注点：能否区分粗能力、物料需求、高级排程三个层次。

9. `APS` 排程依赖哪些关键基础数据？
考官关注点：工艺路线、工时、资源、资源能力、日历、出勤、制造任务、排序规则、排程方案。

10. `有限产能` 和 `无限产能` 排程的区别是什么？
考官关注点：是否理解是否受资源量约束。

11. 在计划执行的业务主线中，从生产订单到现场执行，大致会经过哪些步骤？
考官关注点：生产订单 -> 发布/释放 -> 制造订单 -> 工艺展开 -> 制造任务 -> APS 排程 -> 派工/执行 -> 报工/反馈。

12. 为什么排程前要先确认资源、日历、出勤、排产工时都已经维护好？
考官关注点：是否理解没有基础数据就无法得到可信的排程结果。

13. 什么是 `齐套检查`？它为什么重要？
考官关注点：是否理解它用于判断物料是否满足生产或领料前提。

14. 什么是 `订单释放`？为什么说“发布”和“释放”不是一回事？
考官关注点：发布面向计划域，释放更偏向执行域/车间域。

15. 什么情况下需要对订单进行 `暂停/恢复/取消`？
考官关注点：是否能结合异常、变更、资源冲突、计划调整去回答。

16. 如果工艺路线没有配置好，会对系统产生哪些影响？
考官关注点：无法指定、无法工艺展开、无法生成制造任务、排程失败、执行无依据。

### 4.3 角色权限与平台能力

17. 角色权限模块的作用是什么？
考官关注点：是否理解“把组织职责映射成系统功能权限和模型操作权限”。

18. 为什么角色权限要区分 `管理平台` 和 `车间工作台` 两类场景？
考官关注点：是否理解不同用户群体关注的功能完全不同，混在一起授权容易出错。

19. `角色另存` 这个能力解决了什么问题？
考官关注点：是否理解它用于复用已有权限配置，减少重复配置。

20. 模型授权里常说的 `新增/编辑/删除` 是控制什么的？
考官关注点：是否理解它是对业务对象操作能力的控制，而不只是页面按钮显示。

21. 如果一个用户看得到菜单，但是不能保存数据，可能是什么原因？
考官关注点：功能授权、模型授权、字段权限、组织权限任一环节都可能导致。

### 4.4 配置中心与低代码平台

22. `配置中心` 的作用是什么？
考官关注点：是否理解它是超级管理员做系统初始化和持续配置的统一入口。

23. 配置中心为什么建议按“系统配置 -> 安全配置 -> 工厂资源 -> 产品与工艺 -> 个性化配置”的顺序来做？
考官关注点：是否理解配置之间存在前后依赖。

24. 为什么 `安全配置` 和 `工厂资源` 常被视为上线前必配项？
考官关注点：前者解决账号和权限，后者解决工厂实际业务资源。

25. 低代码平台里 `流程引擎/审批流管理` 的核心能力是什么？
考官关注点：流程模型、审批人、条件分支、并行分支、路由分支、待办办理。

26. 为什么一个审批流程“模型发布了”，还不一定能在业务里发起？
考官关注点：是否理解还需要配置到具体业务流程上。

27. 你理解的低代码平台“核心价值”是什么？
考官关注点：是否能说出“减少硬编码、通过配置快速支持业务变化、提升交付效率”。

### 4.5 Jira、故事点与缺陷

28. `故事点` 是用来衡量什么的？
考官关注点：工作量/复杂度/不确定性，不是简单工时。

29. 一个缺陷从提出到关闭，通常会经历哪些关键流转阶段？
考官关注点：请其按团队当前 Jira 工作流口径回答，不要求背术语，但要讲清“发现、确认、处理、回归、关闭”的逻辑。

30. 提交缺陷时，哪些信息是最不能缺的？
考官关注点：问题现象、复现步骤、预期结果、实际结果、环境、影响范围、截图/日志。

31. 为什么测试人员不能只写“有问题，请开发看一下”？
考官关注点：是否理解缺陷单要可复现、可定位、可协作。

32. 缺陷和测试用例之间是什么关系？
考官关注点：缺陷往往来源于执行测试用例，修复后需要基于对应场景做回归。

33. 培训里提到的“缺陷和用例的核心内容”分别是什么？
考官关注点：用例强调前置条件、步骤、预期；缺陷强调现象、复现、实际/预期差异、证据。

## 五、上机操作题

### 5.1 基础操作题

题目1：请你在系统中找到 `生产订单管理` 页面，并口头说明这个页面可以做哪些核心操作。
考官关注点：是否能快速定位菜单，并能说出发布、释放、齐套检查、指定、暂停/恢复等关键动作。

题目2：请你演示如何查看一个生产订单的关键信息，并说明“工艺路线”在这个页面的作用。
考官关注点：是否能找到订单详情、识别工艺路线字段，并讲清楚它和后续工艺展开/排程的关系。

### 5.2 计划执行主线题

题目3：请按照“计划执行”的主线，讲一遍从订单进入系统到任务执行的大致流程，并在系统中演示其中至少 2 个关键页面。
考官关注点：是否能把“生产订单、制造订单、工艺展开、排程、执行反馈”串起来。

题目4：请在系统里演示如何从生产订单进入制造订单或排程相关页面，并解释当前这一步的业务目的。
考官关注点：不只看会不会点，还看是否理解为什么要做这一步。

### 5.3 权限与平台题

题目5：请你找到角色权限或配置中心入口，并说明这两个模块分别更偏“业务执行”还是“平台配置”。
考官关注点：是否能区分业务模块与平台模块。

题目6：请你说明如果现场操作工和计划员使用同一个角色，可能会有什么问题。
考官关注点：是否理解角色设计和场景隔离的重要性。

## 六、情景追问题

1. 如果生产订单已经发布，但工艺路线选错了，你觉得后面哪几个环节会受影响？

2. 如果 APS 排出来的结果明显不合理，你第一反应会去检查哪些基础数据？

3. 如果一个用户说“我能看到菜单但就是点不了保存”，你会优先从哪些角度排查？

4. 如果缺陷已经修复了，你为什么还要再回到原用例或原业务场景做回归？

## 七、考官简易评分标准

### 7.1 结果判断

| 等级 | 判断标准 |
| --- | --- |
| A | 术语基本清楚，能独立讲通业务主线，系统操作熟练，能主动解释上下游关系 |
| B | 基本概念和页面能找到，主线能讲出大概，但部分术语和原因解释不够准确 |
| C | 只能记住零散页面和按钮，讲不清模块关系，需要较多提示 |
| D | 术语不清、流程混乱、操作路径不熟，需要重新培训 |

### 7.2 重点观察项

- 是否只会背名词，还是能讲清“为什么这么做”
- 是否能把 `工艺路线`、`订单`、`排程`、`执行反馈` 串成一条线
- 是否知道配置模块和执行模块的区别
- 是否理解测试工作中“用例”和“缺陷”的核心内容

## 八、建议收尾提问

1. 今天你觉得最难理解的业务术语是什么？为什么？
2. 如果让你明天开始写“计划执行”相关测试点，你会先从哪个模块下手？
3. 你觉得自己现在更欠缺的是业务理解、系统操作，还是测试表达？
