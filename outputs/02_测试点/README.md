# 测试点目录说明

`outputs/02_测试点/` 用于保存当前项目或需求最终保留的测试点交付物。

这里不再保留 `01_待评审 / 02_已评审 / 03_已沉淀` 这类中间阶段目录，也不再保留模板和历史过程版本。当前目录只保留最终测试点正文。

## 当前目录结构

```text
02_测试点/
├── 测试点/
└── README.md
```

## 目录用途

### 测试点

存放每个需求或模块当前保留的最终测试点 Markdown 文档。

适用内容：

- 当前继续使用的最新测试点版本
- 可直接作为后续测试用例编写基线的测试点正文

不再保留的内容：

- 已被新版本替代的旧版测试点
- 中间过程稿
- 阶段性目录占位文件
- 单独的测试点模板文件

## 整理规则

- 同一份测试点若存在多个版本，默认只保留最新版本。
- 中间过程目录不再保留，旧结构统一收口到 `测试点/`。
- 后续新增测试点产物时，直接放入 `测试点/`，并删除已失效旧版。

## 命名建议

```text
需求编号-需求名称-测试点-V1.2.md
```

示例：

```text
KFRW-00099-月计划管理-测试点-V1.2.md
REQ-00010-火鸡品管理-测试点-V1.0.md
```
