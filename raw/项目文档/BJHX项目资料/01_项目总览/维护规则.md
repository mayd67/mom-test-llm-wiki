# BJHX_PROCESS 维护规则

> 目的：将本仓库从“资料归档”统一为“开发经理项目过程台账”，确保人工或 AI 维护时状态一致、入口唯一、闭环清晰。

## 1. 适用范围

- 本规则适用于 `BJHX_PROCESS` 仓库下所有过程类文档。
- 本规则适用于人工维护和 AI 辅助维护。
- 若局部文档与本规则冲突，以本规则为准。

## 2. 管理原则

### 2.1 单一事实源

同一类状态信息只能有一个主记录，其他文档只能引用，不得各自维护一套状态。

| 信息类型 | 主记录文件 | 说明 |
| --- | --- | --- |
| 项目整体状态 | `项目总控台账.md` | 项目级驾驶舱 |
| 需求状态 | `02_需求与方案/requirements/index.md` | 需求主索引 |
| 风险状态 | `03_问题与决策/risk_register.md` | 风险总台账 |
| 行动项状态 | `03_问题与决策/action_register.md` | 行动项总台账 |
| 决策索引 | `03_问题与决策/decision_index.md` | 决策入口与摘要 |
| 里程碑状态 | `04_进度与里程碑/milestones/index.md` | 计划/实际/偏差 |
| 清单快照 | `06_清单管控/开发任务跟踪表/` | 在线开发任务清单导出的 Excel 快照 |
| 清单说明 | `06_清单管控/说明.md` | 快照规则、字段口径、需求映射说明 |

### 2.2 纪要不承载最终状态

- 会议纪要、沟通摘要记录事实经过。
- 会议形成的需求、风险、决策、行动项，必须同步登记到对应主台账。
- 纪要中可以写“详见某台账条目”，但不作为最终状态依据。

### 2.3 问题、风险、决策、行动项分流

- 问题：已经发生，正在处理或待关闭。
- 风险：尚未发生，但存在概率和影响。
- 决策：已拍板的取舍与结论。
- 行动项：明确责任人和截止时间的待办事项。

禁止在同一文档中长期混合维护这四类状态。

## 3. 目录与文件规则

### 3.1 目录职责

| 目录 | 维护重点 |
| --- | --- |
| `01_沟通与会议` | 会议纪要、沟通事实、原始结论来源 |
| `02_需求与方案` | 需求生命周期、方案、需求基线 |
| `03_问题与决策` | 问题、风险、行动项、决策闭环 |
| `04_进度与里程碑` | 周报、阶段进展、关键节点偏差 |
| `05_部署与运维` | 环境、部署、上线、运维、变更 |
| `06_清单管控` | 在线任务清单快照、转换说明 |

### 3.2 文件命名

- 日期前缀统一使用 `YYYYMMDD`。
- 需求目录统一使用 `REQ-xxxxx_需求名称`。
- 决策文档统一使用 `YYYYMMDD_决策主题.md`。
- 周报统一使用 `YYYYMMDD_周报.md`。
- 问题文档统一使用 `YYYYMMDD_问题简述.md`。
- 在线任务清单快照统一使用 `BJHX-MOM项目开发任务跟踪表_YYYY-MM-DD_HHMM.xlsx`，例如 `BJHX-MOM项目开发任务跟踪表_2026-04-30_1730.xlsx`。
- 原始清单导出文件只追加新增快照，不覆盖历史文件。

### 3.3 必填字段

凡是状态型文档或台账条目，至少包含以下字段：

- `责任人`
- `当前状态`
- `最后更新日期`
- `来源`

缺少以上字段的文档，不视为有效管理记录。

## 4. 状态枚举规则

### 4.1 需求状态

需求状态只能使用以下枚举值：

- `待识别`
- `分析中`
- `待评审`
- `已确认`
- `开发中`
- `测试中`
- `已上线`
- `已关闭`

### 4.2 风险状态

风险状态只能使用以下枚举值：

- `识别中`
- `监控中`
- `已应对`
- `已关闭`

风险等级只能使用：

- `高`
- `中`
- `低`

### 4.3 行动项状态

行动项状态只能使用以下枚举值：

- `待启动`
- `进行中`
- `已完成`
- `已取消`
- `已阻塞`

### 4.4 决策状态

决策状态只能使用以下枚举值：

- `待决策`
- `已决策`
- `已废止`

### 4.5 里程碑状态

里程碑状态只能使用以下枚举值：

- `未开始`
- `进行中`
- `已完成`
- `已延期`
- `已取消`

## 5. 更新触发规则

### 5.1 新增需求

新增需求时，必须同时完成以下动作：

1. 在 `02_需求与方案/requirements/index.md` 新增索引项。
2. 创建对应需求目录与子目录。
3. 在 `original/` 放入原始材料并建立索引。
4. 在 `process/` 开始记录分析过程。

### 5.2 需求状态变化

当需求出现以下变化时，必须同步更新 `02_需求与方案/requirements/index.md`：

- 进入评审
- 客户确认
- 开发启动
- 测试启动
- 上线完成
- 关闭或废弃

### 5.3 会议或沟通后

若会议或沟通形成以下内容，必须同轮同步主台账：

- 新风险或风险等级变化
- 新行动项或行动项状态变化
- 新决策
- 需求状态变化
- 里程碑日期变化

### 5.4 上线或部署变更后

必须同步更新以下内容：

- `05_部署与运维` 下对应部署/变更记录
- `04_进度与里程碑/milestones/index.md`
- 如涉及需求交付，同时更新需求状态

### 5.5 在线清单导出后

从在线开发任务清单导出快照后，必须完成以下动作：

1. 将原始 Excel 归档到 `06_清单管控/开发任务跟踪表/`。
2. 文件名按 `BJHX-MOM项目开发任务跟踪表_YYYY-MM-DD_HHMM.xlsx` 记录导出时间。
3. 若字段口径或转换规则变化，必须同步更新 `06_清单管控/说明.md`。
4. 若正式需求范围或状态变化，必须同步更新 `02_需求与方案/requirements/index.md`。

## 6. AI 维护强制规则

AI 在新增或修改任一文档后，必须执行以下检查：

1. 本次修改是否影响需求主索引。
2. 本次修改是否影响风险台账。
3. 本次修改是否影响行动项台账。
4. 本次修改是否影响决策索引。
5. 本次修改是否影响里程碑台账。

若有影响，必须在同一轮修改中同步完成更新，不得只改正文不改总表。

### 6.1 AI 输出要求

- 不得创造未约定的状态值。
- 不得把会议纪要中的表述直接当作最终状态，除非已同步台账。
- 不得删除历史记录；若状态失效，应改状态，不应直接抹除。
- 若信息不足以更新主台账，应在文档中明确标注 `待确认`，不得擅自补全。

## 7. 推荐维护节奏

### 7.1 每次会后

- 更新会议纪要。
- 抽取行动项、风险、决策到主台账。

### 7.2 每周一次

- 维护周报。
- 检查行动项逾期情况。
- 检查风险等级变化。
- 检查里程碑偏差。
- 修正需求状态。

### 7.3 每个关键节点后

- 更新项目总控台账。
- 更新里程碑状态。
- 记录阶段结论和遗留事项。

## 8. 后续扩展原则

- 先维护总表，再丰富明细。
- 先保证状态可信，再追求文档完整。
- 新增模板或台账时，应优先复用已有状态枚举和字段定义。
