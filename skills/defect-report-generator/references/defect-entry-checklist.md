# 缺陷录入摘要（已内置到 skill）

## 适用环节

- 本 skill 默认适用于缺陷编制阶段
- 缺陷在公司 Jira 平台录入并跟踪
- 测试人员应准确、客观划分严重程度和优先级
- 缺陷编写遵循 Jira 模板及当前 skill 内置的缺陷属性规则
- 对发现的缺陷不做任何评价

## 录入前检查

1. 是否能判断是一条还是多条独立缺陷
2. 是否能明确页面/模块/场景
3. 是否具备最基本的可复现信息：环境、步骤、实际结果、期望结果
4. 若缺少信息，使用 `待补充` / `待确认`，不要编造

## 严重程度定义

- `一级`：操作系统挂起或崩溃
- `二级`：软件本身挂起或崩溃
- `三级`：不能完成软件说明书定义的功能
- `四级`：正常输入或正常操作下出现功能 BUG
- `五级`：非正常输入、边界值或异常输入下出现 BUG
- `六级`：轻微错误，如文本差错、显示问题
- `建议`：当前字段定义未覆盖的易用性优化、扩展延伸或新需求

## 优先级定义

- `P0-重要紧急(120)`：阻碍开发或测试继续进行的系统性故障，如系统无法执行、崩溃、冻结、死循环、非法退出、数据库链接错误、严重数据计算或通讯错误
- `P1-重要不紧急(100)`：严重错误但不影响当前测试继续，如模块功能错误、功能未实现、乱码、链接模块错误、基本按键错误、数据丢失或保存错误
- `P2-紧急不重要(100)`：不影响用户使用的非严重问题，如次要功能未实现、一般 UI 错误、提示信息错误、辅助说明不清、边界或格式约束未实现
- `P3-不重要不紧急(80)`：优化建议、易用性改进、界面显示不恰当、提示文案优化或更好的实现方式
- `暂停`：历史缺陷管理定义中出现过，但当前 Jira CSV 枚举不支持，不能直接落值

## 到期日时限

- `P0-重要紧急(120)` -> 缺陷提出日当日
- `P1-重要不紧急(100)` -> `缺陷提出日 + 1D`
- `P2-紧急不重要(100)` -> `缺陷提出日 + 3D`
- `P3-不重要不紧急(80)` -> `缺陷提出日 + 5D`

## 描述写法

必须使用：

```text
环境：测试环境：http://192.168.30.186:32053/ant-web/#/user/login
问题描述：...
操作步骤：
1. ...
2. ...
实际结果：...
期望结果：...
```

## 描述禁忌

不要写：

- 主观评价，如“设计差”“低级错误”“研发未自测”
- 无依据归因，如“根因一定是后端接口问题”
- 无法确认的账号、模块、Sprint、版本、附件地址

## 输出前检查

1. 是否一行表头、多行缺陷
2. 是否每条缺陷都可独立理解
3. 是否所有枚举字段都落在允许值中
4. 是否 `影响范围分析` 单独输出
5. 是否待确认项已写入 `描述`
6. `概要` 若包含页面/模块前缀，是否统一使用中文全角括号 `【】`
7. `到期日` 格式是否为 `yyyy/MM/dd`
