# Jira CSV 导入规则（KMMOM 缺陷，内置录入规则）

## 适用范围

将随手写的问题描述、聊天片段、截图摘要、日志摘要或不完整缺陷草稿，整理为可直接导入 Jira 的缺陷 CSV。

默认用于缺陷编制阶段；目标项目上下文固定为 `KMMOM-3(KMMOM3)`。

快速执行时，先读 [defect-entry-checklist.md](defect-entry-checklist.md) 再回到本文件查字段细则。

## 录入原则

1. 缺陷录入必须遵循公司 Jira 模板及当前 skill 内置的缺陷属性规则。
2. 测试人员对 `缺陷严重程度` 与 `优先级` 的划分要准确、客观。
3. 对发现的缺陷不做任何评价；描述中只保留事实、现象、步骤、结果和期望。
4. 无法确认的信息不编造；可写 `待补充`、`待确认` 或留空。

## 默认列顺序

按以下顺序输出，不增删表头：

1. `问题类型`
2. `状态`
3. `概要`
4. `优先级`
5. `模块`
6. `缺陷严重程度`
7. `对用户的影响程度`
8. `描述`
9. `影响范围分析`
10. `责任人`
11. `测试责任人`
12. `缺陷产生者`
13. `到期日`
14. `使用的版本`
15. `修复的版本`
16. `Sprint`

## 固定值与默认值

- `问题类型` 固定：`缺陷`
- `状态` 默认：`缺陷编制中`
- `Sprint` 默认输出 Jira 实际值；优先从项目实际 Sprint 目录按当前日期自动选择，无法读取时兜底为 `276`
- `使用的版本` 默认规则：
  - 2026-04-15 之前：`KMMOM Cloud V3.4`
  - 2026-04-15（含）之后：`KMMOM Cloud V3.5`

## 枚举字段

### `状态`

只能从以下值中选择：

- `缺陷编制中`
- `缺陷分派中`
- `打开`
- `打开（重新打开）`
- `打开（验证失败）`
- `已修复待签发`
- `已签发测试中`
- `缺陷关闭`

### `优先级`

只能从以下值中选择：

- `P0-重要紧急(120)`
- `P1-重要不紧急(100)`
- `P2-紧急不重要(100)`
- `P3-不重要不紧急(80)`

历史缺陷管理定义中出现过 `暂停` 表述，但当前 CSV 导入枚举不支持；遇到该值时必须追问或在待确认中标记，不能直接落值。

默认兜底：`P1-重要不紧急(100)`。

### `模块`

只能从以下值中选择：

- `01-mom-platform`：系统管理、主数据
- `02-mom-mes`：计划管理、制造执行
- `03-mom-aps`：APSP 排程
- `04-mom-wms`：仓储物流
- `05-mom-ems`：设备
- `06-mom-tms`：工装
- `07-mom-bds`：统计分析
- `08-mom-approve`：审批流

根据用户描述关键词推断；无法判断时兜底 `01-mom-platform`，并在 `描述` 中标记待确认。

### `缺陷严重程度`

只能从以下值中选择：

- `一级`：操作系统挂起或崩溃
- `二级`：软件本身挂起或崩溃
- `三级`：不能完成软件说明书定义的功能
- `四级`：正常输入或正常操作下出现功能 BUG
- `五级`：非正常输入、边界值或异常输入下出现 BUG
- `六级`：轻微错误，如文本差错、显示问题
- `建议`：当前字段定义未覆盖的优化建议、拓展延伸或新需求

默认兜底：`三级`。

### `对用户的影响程度`

只能从以下值中选择：

- `无`
- `高`
- `中`
- `低`

默认兜底：`中`。

### `使用的版本`

允许值：

- `KMMOM Cloud V3.2`
- `KMMOM Cloud V3.3`
- `KMMOM Cloud V3.4`
- `KMMOM Cloud V3.5`

### `修复的版本`

允许值：

- `KMMOM Cloud V3.2`
- `KMMOM Cloud V3.3`
- `KMMOM Cloud V3.4`
- `KMMOM Cloud V3.5`

默认规则：

- 2026-04-15 之前：默认 `KMMOM Cloud V3.4`。
- 2026-04-15（含）之后：默认候选值切换为 `KMMOM Cloud V3.5`，但必须先征得用户确认；未确认时不要静默落值。

### `Sprint`

CSV 中输出 Jira 实际值，而不是显示名。优先顺序如下：

1. 用户明确给出并能在项目 Sprint 列表中匹配
2. 通过项目 Sprint 目录按当前日期自动推荐
3. 无法读取项目 Sprint 时再回退静态映射或默认值

静态映射兜底如下：

- `V3.4-a1(260131)` -> `263`
- `V3.4-a2(260214)` -> `264`
- `V3.4-a3(260307)` -> `270`
- `V3.4-a4(260321)` -> `271`
- `V3.4-a5(260404)` -> `274`
- `V3.4-a6(260418)` -> `276`

默认兜底：`276`。

## 内置判定规则

### `优先级`

优先使用用户明确给出的值；否则按当前 skill 内置优先级定义推断：

- `P0-重要紧急(120)`：阻碍开发或测试继续进行的系统性故障；系统无法执行、崩溃、冻结、死循环、非法退出、数据库链接错误、严重数据计算或通讯错误。
- `P1-重要不紧急(100)`：严重错误但不影响当前测试继续；模块功能错误、功能未实现、乱码、链接模块错误、基本按键错误、数据丢失、破坏、计算或保存错误。
- `P2-紧急不重要(100)`：不影响用户使用的非严重问题；次要功能未实现、一般 UI 错误、提示信息错误、辅助说明不清、边界或格式约束未实现。
- `P3-不重要不紧急(80)`：优化建议、界面显示优化、易用性改进、更好的实现方式。

### `到期日`

- 用户明确给出时优先保留。
- 否则按当前 skill 内置时限规则推算；默认以脚本执行时的当前系统日期为起算日，除非用户明确提供业务日期：
  - `P0-重要紧急(120)` -> 缺陷提出日当日
  - `P1-重要不紧急(100)` -> `缺陷提出日 + 1D`
  - `P2-紧急不重要(100)` -> `缺陷提出日 + 3D`
  - `P3-不重要不紧急(80)` -> `缺陷提出日 + 5D`
- 输出格式固定为 `yyyy/MM/dd`，以匹配 Jira CSV 导入默认日期格式。

## 字段映射规则

### `概要`

- 根据原始素材自动生成。
- 保持短而具体，避免“功能异常”“页面有问题”。
- 推荐格式：`【页面/模块】 执行某操作后出现某异常`。
- 若原始素材中的概要前缀使用英文半角括号 `[]`，输出时必须统一规范化为中文全角括号 `【】`。

### `描述`

严格使用以下结构：

```text
环境：测试环境：http://192.168.30.186:32053/ant-web/#/user/login
问题描述：...
操作步骤：
1. ...
2. ...
实际结果：...
期望结果：...
```

规则：

- `问题描述` 必须客观、中性，只写现象和条件，不写评价。
- `操作步骤` 要可复现、可编号；缺失时写 `1. 待补充`。
- `期望结果` 优先参照测试用例、需求或产品定义。
- 如果存在额外环境信息，可追加在默认环境后，但不要写“本地开发环境”。
- 如果提到截图、日志或录屏但没有可直接使用的地址，不要自动追加到 Jira `描述` 字段；可保留在原始素材中待后续补充。
- 缺失信息不编造；正文缺失内容可写“待补充”，但不要在 Jira `描述` 字段末尾追加“待确认”块。

### `影响范围分析`

- 单独输出，不并入 `描述`。
- 至少覆盖受影响角色、业务流程与数据范围。
- 未知时填：`影响范围待确认（请补充受影响角色、流程与数据范围）`。

### `责任人`、`测试责任人`、`缺陷产生者`

- 只填写 Jira 可识别账号。
- 格式为“姓氏全拼+名字首字母”，例如 `mayd`。
- 当用户输入为中文姓名时，默认按“姓氏全拼 + 名字首字母”生成 Jira 账号，例如 `李飞 -> lif`、`马雨逗 -> mayd`。
- 原始素材优先；若未提供，但能依据中文姓名规则生成，则直接生成对应 Jira 账号。
- 默认不因账号字段缺失阻塞 CSV 生成；无法依据中文姓名规则生成时可直接留空，不写占位文本。
- 仅当用户明确要求必须补齐责任字段时，才追问用户补充账号。
- 脚本模式下可通过 `--owner`、`--qa-owner`、`--creator` 直接补填。

## 安全规则

1. 不编造账号、状态、版本、修复的版本、Sprint、模块或附件地址。
2. 允许推断的字段仅限 `优先级`、`模块`、`缺陷严重程度`、`对用户的影响程度`，且必须落在枚举值内。
3. 不能确定时使用规则中的默认值，并在 `描述` 中写清待确认项。
4. 一个 CSV 仅保留一行表头，每条缺陷对应一行数据。
5. 默认生成文件时，输出到 `outputs/04_测试执行/03_缺陷导出/` 目录。
6. 默认文件名格式严格为 `jira_import_(MM-DD-NNN).csv`，例如 `jira_import_(03-25-001).csv`；日期部分默认取脚本执行时的当前系统日期，同一天重复生成时流水号递增。
7. 若显式传入 `--output` 且为 `.csv` 文件名，该文件名也必须符合当日 `jira_import_(MM-DD-NNN).csv` 格式；否则脚本应报错，不能静默生成自定义命名文件。默认不要传入固定历史 `--today` 来影响文件名日期与到期日计算。
