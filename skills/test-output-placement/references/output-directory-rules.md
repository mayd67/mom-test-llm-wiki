# 交付物目录规则

## 1. 使用目标

本规则用于统一判断测试工作产物应该进入 `raw/`、`wiki/` 还是 `outputs/`，以及进入 `outputs/` 后应该落到哪个一级目录和状态子目录。

## 2. 三层边界

### `raw/`

放原始输入资料，例如：

- 需求文档
- 原型图
- 会议纪要
- 接口资料
- 外部附件

### `wiki/`

放长期可复用知识，例如：

- 方法规范
- 模板说明
- 领域知识
- skill 入口页
- 稳定测试策略

### `skills/`

放可执行或可复用的 skill 本体，例如：

- `SKILL.md`
- `agents/openai.yaml`
- `references/`
- `assets/`
- `scripts/`

### `outputs/`

放当前需求、当前项目、当前阶段的实际交付物，例如：

- 需求评审结果
- 测试点
- 测试用例
- 测试数据导入包
- 缺陷导入文件
- 测试报告

## 3. 一级目录映射

| 产物类型 | 推荐目录 | 典型文件 |
| --- | --- | --- |
| 需求评审问题、澄清、风险 | `outputs/01_需求评审/` | `.md`、`.xlsx` |
| 测试点分析结果 | `outputs/02_测试点/` | `.md` |
| 测试用例工作稿、评审稿、导入版 | `outputs/03_测试用例/` | `.md`、`.xlsx` |
| 测试计划、执行记录、缺陷导出、测试报告 | `outputs/04_测试执行/` | `.md`、`.xlsx`、`.csv` |
| 用户操作手册、视频脚本、培训讲稿 | `outputs/05_用户操作手册/` | `.md`、图片目录 |
| 测试数据种子、导入包、场景数据目录 | `outputs/06_测试数据/` | `.json`、`.xlsx`、`.zip`、目录 |
| 历史版本、旧目录散落产物、废弃交付物 | `outputs/99_归档/` | 任意 |

## 4. 二级目录规则

### `outputs/02_测试点/`

- `01_待评审/`：测试点初稿，尚未评审
- `02_已评审/`：评审通过，可继续写测试用例
- `03_已沉淀/`：已提炼出共性规则，但仍保留交付物属性

### `outputs/03_测试用例/`

- `01_待评审/`：测试用例初稿或草稿
- `02_已评审/`：评审通过的测试用例正文
- `03_MeterSphere导入/`：用于系统导入的 Excel 文件
- `04_已沉淀/`：可复用的标准用例样例

### `outputs/04_测试执行/`

- `01_测试计划/`：阶段计划、排期、范围说明
- `02_执行记录/`：执行明细、结果留痕、验证记录
- `03_缺陷导出/`：Jira、MeterSphere 等导入导出文件
- `04_测试报告/`：阶段报告、结项报告
- `05_回归验证/`：回归范围、回归记录、回归结论

### `outputs/06_测试数据/`

- 一个业务场景一个子目录，例如 `大疆无人机/`
- 场景目录下推荐保留：
  - `*_seed.json`
  - `*_import/`
  - `*_import.zip`
  - `说明文件.md`

## 5. 目录判定规则

### 测试点

- 还在分析或待评审：放 `outputs/02_测试点/01_待评审/`
- 已评审确认：放 `outputs/02_测试点/02_已评审/`
- 已抽出稳定规则：放 `outputs/02_测试点/03_已沉淀/`

### 测试用例

- Markdown 工作稿：优先 `outputs/03_测试用例/01_待评审/`
- 评审确认后的 Markdown：优先 `outputs/03_测试用例/02_已评审/`
- MeterSphere 导入版：优先 `outputs/03_测试用例/03_MeterSphere导入/`
- 标准样例或通用模板化成果：优先 `outputs/03_测试用例/04_已沉淀/`

### 测试数据

- 如果是种子、导入包或场景说明：放 `outputs/06_测试数据/场景名称/`
- 如果是数据生成 skill 本体、模板与脚本：放 `skills/mom-business-data-generator/`
- 如果只是数据能力说明页、使用建议或知识入口：放 `wiki/01_MOM产品相关文档/06_测试数据/`

### 测试执行

- 如果是执行过程文件、报告、缺陷导出：放 `outputs/04_测试执行/`
- 如果是缺陷写作方法、模板、规则：放 `wiki/01_MOM产品相关文档/07_缺陷管理/`

## 6. 命名规则

### 通用命名

```text
需求编号-模块名称-交付物类型-V1.0.md
需求编号-模块名称-交付物类型-YYYYMMDD.md
项目名称-场景名称-交付物类型-V1.0.xlsx
```

### 测试点

```text
DNW31500-智能问数-测试点-V1.0.md
```

### 测试用例

```text
DNW31500-智能问数-测试用例-V1.0.md
DNW31500-智能问数-测试用例-MeterSphere导入-V1.0.xlsx
```

### 测试数据

```text
大疆无人机-测试数据种子-V1.0.json
大疆无人机-测试数据导入包-V1.0.zip
```

## 7. 根目录约束

- `outputs/` 根目录只保留 README 和标准编号目录
- 不直接堆放业务产物
- 如果根目录出现单个业务文件，应迁移到对应编号目录

## 8. 状态不明时的处理

- 不清楚是否已评审：不要直接放入“已评审”
- 不清楚是否应沉淀：先保留在业务目录，不要提前进入 `wiki/`
- 不清楚是否为历史文件：先说明假设，再由用户确认是否归档
