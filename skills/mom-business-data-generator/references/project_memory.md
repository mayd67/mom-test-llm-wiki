## 一、用途

本文件用于沉淀本项目在多轮对话中已经确认的关键口径，避免因为上下文压缩、会话切换或模型变更导致约定丢失。

后续任何人在本仓库继续工作时，建议先读全局偏好，再读本文件和交接记录，再继续生成新的种子、Excel 或 skill 文档。

当前建议读取顺序如下：

1. 全局偏好文件（可选，例如 `$CODEX_HOME/user_preferences.md`；如不存在可跳过）
2. `references/project_memory.md`
3. `references/handoffs.md`
4. `references/template_relationships.md`
5. `references/template_constraint_dictionary.md`
6. `references/scenario_blueprints.md`
7. `README_SHARE.md`（当需要交接、迁移或团队共享时）

## 二、当前项目目标

本项目的核心目标是：

- 基于既有四份 Excel 模板；
- 快速生成可导入 MOM 系统的主数据种子；
- 再导出为与模板一致的 Excel；
- 同时支持售前演示、方案验证、行业场景快速出数。

## 三、已经确认的长期规则

### 1. 输出语言

- 所有对用户的输出默认使用中文。
- 所有新生成的 skill 说明默认使用中文。
- 说明文档、参考文档、约束文档默认使用中文。

### 2. 编码规则

- 文档类文件优先使用 `UTF-8 with BOM`，避免 Windows 下直接打开乱码。
- JSON 种子文件建议使用 `utf-8-sig` 写出。
- 如果终端显示乱码，不代表文件本身有问题，优先用程序回读文件验证。
- 如果用户可能把多套数据导入同一个环境，则每次新生成的一套数据都必须使用新的编码命名空间，不能与历史场景或历史批次重复。
- 组织、物料、工艺、订单等对象默认采用“对象前缀 + 场景/批次命名空间 + 对象语义”模式编码，例如 `ADM-AE20T01-POWER`、`BIZ-AE20T01-ASM`、`MAT-AE20T01-ENG`。
- 用户编码默认采用更短、更易读的流水码风格，例如 `K7101`、`K7102`、`K2001`；既保持简短，也保留跨场景唯一性。
- 同一套数据的修订可以复用原命名空间；只要是新生成的一套独立数据，就必须分配新的命名空间批次号。

### 3. 模板强约束

- 不允许凭经验填写下拉值。
- 生成的数据必须按照当前提供的模板生成，必须命中模板的真实字段、真实下拉枚举、真实引用关系。
- 所有引用关系统一写编码，不写名称。
- 凡是带版本号的引用，版本号必须同步填写。
- 如果用户有“多套数据导入同一环境”的使用方式，则不仅物料编码，所有主数据编码都必须全局唯一。
- 当前 skill 主要用于 POC 验证时，默认采用最低安全口径：`用户安全等级 = 一般`，`*密级 = 公开`；只有用户明确要求时才提高等级。
- 如果用户提供了业务文档、方案文档、BOM 清单、工艺文档、组织清单或订单计划，则这些文档应作为建模事实来源，优先级高于历史样例和蓝图默认值。

### 4. 顶层组织规则

- 行政组织顶层公司的父组织编码默认使用 `0`。
- 业务组织顶层公司的父组织编码默认使用 `0`。

### 5. 用户命名规则

- 用户名称使用真实风格中文姓名。
- 不使用“张三、李四”这类明显占位名。
- 不使用真实企业未经授权的员工花名册。

### 6. 建模模式规则

本项目已经确认：

- skill 必须同时支持单工厂模式和多工厂模式。
- 不能默认只按多工厂做，也不能默认只按单工厂做。
- 必须先判断场景，再决定采用哪种模式。

判定原则：

- 单零件、单模块、单工艺段，优先单工厂模式。
- 整机、总成、复杂装备，优先多工厂模式。
- 存在外协时，无论单工厂还是多工厂，都要考虑供应商和外委工序。

### 7. 建模完整性规则

无论场景大小，以下对象是底线：

- 行政组织
- 业务组织
- 用户
- 工作中心
- 物料
- MBOM / MBOM节点
- 工艺路线
- 工艺路线工序
- 工艺路线工序序列
- 工艺路线工序物料
- 工艺路线工步

如果项目目录中存在 `生产订单_模板.xlsx`，则还应补齐：

- 生产订单
- 备料清单

### 8. 生成方式规则

- 大体量数据优先通过脚本循环生成。
- 不推荐手写超长 JSON。
- 新场景优先先写种子脚本，再生成 JSON，再导出 Excel。

### 9. 专业数据口径规则

- 生成结果应优先达到“专业、拟真、可讲解”的售前展示口径，而不是明显 demo 化的数据。
- 数据需要能够支撑向客户讲解组织协同、资源配置、MBOM 结构和工艺执行逻辑。
- 允许基于公开资料和行业常识构建拟真主数据，但不能伪装成 OEM 保密数据包。

### 10. 工厂组织与用户细化规则

- 工厂组织默认优先生成全层级：`公司 → 工厂 → 部门 → 车间 → 工段 → 班组`。
- 如果场景需要适度收敛，可采用简化层级：`公司 → 工厂 → 工段 → 班组`。
- 用户应按组织层级和业务角色分配，不要只挂在公司层或工厂层。
- 常见角色应尽量补齐：工艺工程师、生产计划员、班组长、质量员、质量主管、维修工、设备保养员、仓库管理员、操作工等。
- 用户姓名应使用真实风格中文脱敏姓名，不使用占位名，也不使用真实可识别员工名单。

### 11. 设备、工作中心、工装与外协规则

- 设备与工作中心应尽量细化到真实制造单元颗粒度，便于体现专业制造能力。
- 工装工具应作为独立资源对象补齐，不应在专业场景中省略。
- 应根据真实场景区分专用工装、通用工具、工装备件，以及装配夹具、检具、吊具、转运工装、扭矩工具等。
- `工装工具`、`物料`、`MBOM` 的 `发布人` 必须填写 `用户` sheet 中的真实引用编码；默认自动匹配工装工程师、工艺总师、工艺平台主管或工艺工程师。`工艺路线` sheet 的 `发布人` 当前统一留空。
- 当前模板未提供工装检定策略、工装保养策略的主数据定义表，因此 `工装检定策略关系` 与 `工装保养策略关系` 默认不生成数据。
- 只有用户明确提供目标系统中已存在的合法策略编码时，才生成工装策略关系；生成时必须引用真实存在的工装版本号、工装编码、工厂组织编码和合法策略编码。
- 工作中心类型必须严格使用模板真实枚举值。
- 只有当工作中心类型为 `外委` 时，才生成 `工作中心与供应商的关系`；若不存在外委工作中心，则该 sheet 保持空表。
- 供应商不仅包括供货商，也包括外协加工商、外委服务商。
- 多工厂场景下，每个专业工厂都应建立自己相对独立的设备、工作中心、库房和人员体系。

### 12. 生产订单规则

- 如果目录中存在 `生产订单_模板.xlsx`，则订单数据也应纳入同一套场景输出。
- 生产订单优先基于已生成的 `物料`、`MBOM`、`工艺路线` 自动派生，不生成脱离主数据的孤立订单。
- `生产订单` Sheet 中的物料、BOM、工艺路线、计划员、所属组织全部按编码填写。
- `备料清单` 优先由 `工艺路线工序物料` 展开，`工序编码` 与 `工序名称` 必须和对应工艺路线工序一致。
- 若某订单对应物料存在 MBOM，则应优先回填 BOM 编码和版本号；若不存在，则 BOM 字段可留空。
- 订单编码必须带场景命名空间，确保不同场景、不同批次可以共同导入同一环境。

### 13. 文档驱动生成规则

- 本项目支持“用户先给文档，再按文档生成数据”的工作方式。
- 常见输入文档包括：售前解决方案、产品样册、PPT/PDF、BOM Excel、工艺规程、组织架构、资源台账、生产计划。
- 有文档时，应先抽取文档中的显式事实，再映射到四个模板；不能直接跳过文档按历史样例硬套。
- 若文档中已有产品名称、型号、图号、规格、工厂分工、供应商、计划数量、日期等信息，应优先采用。
- 若文档没有编码，则按命名空间规则自动编码；若文档已有内部编码，则优先沿用并校验唯一性。
- 若文档信息不完整，才允许用行业常识、场景蓝图和历史样例补齐，并应在结果说明中明确哪些是补齐项。
- 若多份文档信息冲突，优先级默认为：用户本轮明确要求 > 用户提供的最新文档 > 模板真实约束 > 场景蓝图默认值 > 历史样例。
- 多工厂场景下，每个专业工厂都应建立自己相对独立的工装体系。

### 12. MBOM 与工艺深度规则

- MBOM 必须存在 0 层根节点，根节点父节点编码使用 `0`。
- 0 层节点对应的物料应为主产品或最终交付产品。
- 物料分层应尽量体现原材料、毛坯、阶段件、半成品、模块件、总成件、成品的真实链条。
- 工艺路线不应只保留演示性工序，需尽量体现真实制造过程。
- 应根据场景合理补齐准备、上料/装夹、关键加工或装配、转运、检验、热处理/表处、调试、终检、包装/入库等环节。
- 工步应尽量体现关键设备、关键质量控制点和关键制造动作，保证看起来是一套专业数据，而不是简单 demo。

### 13. 分发复用规则

- 对外共享时，不单独发送 `SKILL.md`，而是共享 `mom-template-seed-generator/` 整个目录和对应模板文件。
- 文档中的路径默认使用工作区相对路径或占位路径，不记录个人工作站绝对路径。
- 全局偏好文件属于可选增强项；没有时不阻塞使用，按本项目记忆文件和模板约束继续执行。
- 如果要给其他 AI 配置复用，应同时带上 `README_SHARE.md` 和 `DELIVERY_PACKAGE_CHECKLIST.md`，避免别人只拿到 skill 文本却缺少目录结构、交付方式和运行说明。
- 如果用户提供外部 Word/PDF/PPT/BOM/工艺规程等资料，应先抽取事实，再映射到模板；不能因为分发复用而跳过文档事实。

## 六、已确认的典型场景口径

### 1. 航空发动机场景

已确认：

- 可做单制造中心演示版；
- 也应支持多工厂协同版；
- 多工厂版需要体现铸造、锻造、机加、热表、模块装配、总装、试车、外协等。

### 2. 数控机场景

已确认：

- 可做整机多模块制造场景；
- 也应支持单工厂场景，例如单工厂机加工传动轴、单工厂装配主轴模块。

## 七、当前推荐工作方式

每次接到新需求，建议按以下顺序执行：

1. 先判断这是单工厂还是多工厂；
2. 再判断是否存在外协；
3. 再从 `scenario_blueprints.md` 选蓝图；
4. 再生成组织、资源、物料、工艺；
5. 最后执行模板校验和 Excel 导出。

## 八、如果未来上下文再次丢失，至少要保住什么

如果未来会话被截断、压缩或更换模型，至少要保住以下共识：

- 输出一律中文；
- 文档避免乱码，优先 `UTF-8 with BOM`；
- 模板下拉枚举必须校验；
- 顶层组织父编码是 `0`；
- skill 同时支持单工厂和多工厂；
- 外协通过供应商 + 外委工序建模；仅当存在 `外委` 工作中心时才生成 `工作中心与供应商的关系`；
- `工装工具`、`物料`、`MBOM` 的 `发布人` 必须使用 `用户` sheet 中已存在的 `*编号`，默认按专业角色自动映射；`工艺路线` sheet 的 `发布人` 留空；
- 工装检定/保养策略关系在缺少策略定义表时默认留空；
- 如果存在 `生产订单_模板.xlsx`，则订单和备料清单也要按同一场景一起生成；
- 订单优先由物料 + MBOM + 工艺路线自动派生，避免脱离主数据单独编单；
- 新场景优先脚本化生成，而不是手写大段 JSON。
- 容量档位可配置：`标准版`（默认）、`大体量版`、`超大体量版`；可通过 `seed.metadata.volume_profile` 或环境变量 `MOM_SEED_VOLUME_PROFILE` 指定。默认按 `标准版` 生成，且允许突破模板预留展示行数，只要模板校验通过即可。
- 用户中应显著体现一线操作工占多数的 MOM 使用特征。
- 设备、工作中心、物料、MBOM、工艺路线工序和工步应按结构化规则同步放量。
- 工艺路线工序序列默认采用 `ES` 接续关系，非用户明确要求时不默认 `SSEE`。
