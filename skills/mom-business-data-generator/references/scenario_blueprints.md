# 场景建模蓝图

## 一、用途

本文件用于给 MOM 模板种子生成器提供统一的场景判定和建模蓝图。

目标不是直接存放某个行业的数据，而是定义一套可反复复用的建模套路，让后续任何新场景都能先判断：

- 应该用单工厂模式，还是多工厂模式；
- 在所选模式下，应该套哪一种业务蓝图；
- 最少需要建立哪些对象；
- 哪些对象可以简化，哪些对象不能省略。

## 二、统一判定顺序

每次接到新需求时，按以下顺序判断：

### 第一步：判断交付对象是什么

优先判断用户要的是哪一类对象：

- 单零件
- 单部件
- 单模块
- 整机/总成
- 产线级或工厂级场景演示

经验规则：

- 单零件、单部件、单模块，优先考虑单工厂模式。
- 整机、总成、复杂装备，优先考虑多工厂模式。

### 第二步：判断是否存在真实跨厂流转

如果存在以下任一情况，优先考虑多工厂模式：

- 原材料、毛坯、热处理、机加、装配、试验由不同工厂完成。
- 用户明确提到多个工厂、多个专业、多个制造中心。
- 需要体现厂际转工、半成品转运、跨组织协同。

如果不存在，或者用户只关心某一个工厂内的业务，则优先采用单工厂模式。

### 第三步：判断是否需要外协

无论是单工厂还是多工厂，只要满足以下情况之一，就要加入外协建模：

- 用户提到外协、外委、委外加工、供应商配套。
- 某道工序明显不在当前工厂能力范围内。
- 为了贴近真实业务，需要补充热处理、表面处理、钣金、标准件、电控等外协过程。

### 第四步：选择蓝图

判定完后，选择最接近的蓝图，而不是临时拼装：

- 单工厂机加工蓝图
- 单工厂装配蓝图
- 单工厂热处理/表面处理蓝图
- 单工厂检测/试验蓝图
- 多工厂离散制造蓝图
- 多工厂总装协同蓝图
- 多工厂 + 外协混合蓝图

### 第五步：套用专业深度规则

#### 1. 组织层级

- 默认优先生成完整层级：`公司 → 工厂 → 部门 → 车间 → 工段 → 班组`。
- 如果场景需要适度简化，可采用：`公司 → 工厂 → 工段 → 班组`。
- 单工厂场景至少应保证工厂下能分解到车间/工段和班组。
- 多工厂场景中，每个专业工厂都应有自己的组织链条，而不是只挂一个工厂名称。

#### 2. 用户与角色

- 用户应按组织层级和业务角色分布，不要只集中在公司层。
- 常见角色默认应考虑：工艺工程师、生产计划员、班组长、质量员、质量主管、维修工、设备保养员、仓库管理员、操作工等。
- 如场景涉及总装、试车、热表、机加、电气、仓储等专业，应补齐对应专业岗位。
- 姓名应使用真实风格中文脱敏姓名，避免占位名和真实可识别人员名单。

#### 3. 设备、工装与工作中心

- 设备应与真实制造能力对应，例如机加设备、热处理设备、检测设备、装配工装、试验台等。
- 工装工具应按真实场景补齐，例如夹具、检具、吊具、扭矩工具、转运工装、装配胎架、专用刀具车等。
- 对需要周期检定或周期保养的工装，应同步生成 `工装检定策略关系` 与 `工装保养策略关系`。
- 工装策略关系应引用真实工装版本号、工装编码和工厂组织编码。
- 当前模板只导出了工装与策略的关系表，未导出策略主数据表；策略编码应优先引用目标系统已有合法编码。
- 工作中心应细化到真实制造单元，不要只放“机加工中心”“装配中心”这种过泛对象。
- 工作中心类型必须命中模板真实枚举。
- 外协工作中心必须关联供应商。
- 供应商既可以是供货商，也可以是外协加工商或外委服务商。

#### 4. 物料与 MBOM

- MBOM 必须具备 0 层根节点，父节点编码使用 `0`。
- 0 层节点对应物料应为主产品或最终交付产品。
- 应尽量体现原材料、毛坯、阶段件、半成品、模块件、总成件、成品的真实链条。
- 多工厂场景中，跨厂流转后的阶段件宜独立建料，避免只保留最终成品。

#### 5. 工艺路线与工步

- 工艺路线应尽量按真实制造过程展开，不要只保留少量演示性工序。
- 机加工场景宜体现备料、下料、粗加工、半精加工、热处理/表处、精加工、清洗、防锈、检验、入库等链条。
- 装配场景宜体现领料、预装、部装、总装、调试、参数记录、终检、包装/入库等链条。
- 复杂多工厂场景默认以 `加工`、`检验`、`外委`、放行节点表达执行过程，不默认生成 `厂内转工`、`厂际转工` 工序。
- 若用户明确要求“一级工艺 + 生产项目部一级生产订单”，可额外增加一层协同主线：`生产项目部` 作为工厂型组织持单，其下按参与工厂拆分协同排产中心，一级工艺工序挂协同排产中心以表达按工厂产能协同排产。
- 工步应体现关键动作、关键设备和关键质量控制点，保证结果看起来是一套专业数据。

## 三、单工厂蓝图

## 3.1 单工厂机加工蓝图

### 适用场景

- 高精度传动轴
- 箱体类零件
- 法兰、壳体、轴套、盘类件
- 单工厂内部完成粗加工、精加工、检验

### 最小对象集

- 一个主工厂业务组织
- 一组机加工工作中心
- 对应机加工设备
- 原材料库、在制库、成品库
- 一个零件物料
- 一个 MBOM
- 一条机加工工艺路线
- 工序：粗加工、热处理（可选）、精加工、检验

### 可选增强

- 若热处理外协，则加入供应商和外委工序
- 若需要体现半成品流转，可增加“粗加工件”“热处理后件”“精加工成品件”

## 3.2 单工厂装配蓝图

### 适用场景

- 主轴模块装配
- 减速箱装配
- 电柜装配
- 刀库装配
- 液压站装配

### 最小对象集

- 一个装配工厂或装配车间
- 装配工作中心
- 装配工装与工具
- 外购件/自制件物料
- 模块级 MBOM
- 一条装配工艺路线
- 工序：预装、总装、调试、终检

### 可选增强

- 增加扭矩记录、间隙检测、参数烧录、联调验证等工序工步

## 3.3 单工厂热处理/表面处理蓝图

### 适用场景

- 调质、淬火、回火
- 渗碳、氮化
- 喷涂、电镀、磷化、发黑等表面处理

### 最小对象集

- 一个热表工厂或专业车间
- 热处理炉/涂覆设备等设备资源
- 待处理件和处理后件物料
- 一条热表工艺路线
- 工序：装炉、处理、冷却/清洗、检验

## 3.4 单工厂检测/试验蓝图

### 适用场景

- 三坐标检测
- 精度检测
- 性能试验
- 空载跑合或负载试车

### 最小对象集

- 一个检测/试验工厂或车间
- 检测设备/试验台
- 待检件或待试件物料
- 一条检测或试验工艺路线
- 工序：准备、检测/试验、结果分析、放行

## 四、多工厂蓝图

## 4.1 多工厂离散制造蓝图

### 适用场景

- 航空发动机
- 数控机床整机
- 汽车发动机总成
- 复杂机械装备

### 工厂拆分建议

可按以下专业拆分：

- 铸造工厂
- 锻造工厂
- 机加工工厂
- 热表处理工厂
- 部件装配工厂
- 电气工厂
- 总装工厂
- 试验/试车工厂
- 仓储物流中心
- 质量中心

### 最小对象集

- 多个业务组织，每个组织对应不同专业工厂
- 每个工厂建立自己的设备、工作中心、库房、用户
- 物料体现从毛坯到半成品再到成品的阶段件链条
- MBOM 能挂接多个阶段件和模块件
- 工艺路线体现厂内加工、检验和总装；跨工厂协同默认不再通过转工工序类型表达。

## 4.2 多工厂总装协同蓝图

### 适用场景

- 以整机交付为中心，但大量部件来自不同工厂
- 用户重点关注跨厂协同和工厂级协同计划排产

### 特点

- 上游各专业工厂只负责模块或关键件
- 总装工厂负责整机集成
- 试车工厂负责性能验证和最终放行
- 若系统未实现转工工序口径，则跨厂协同优先通过一级工艺、生产项目部一级订单和协同排产中心体现。

## 4.3 多工厂 + 外协混合蓝图

### 适用场景

- 主流程由内部多工厂完成
- 某些专业工序或标准件依赖外协/供应商

### 特点

- 内部工厂建模 + 外协供应商建模同时存在
- 需建立：
  - 供应商
  - 工作中心与供应商关系
  - 外委工序
- 外协件可以是原材料、标准件、表处件、热处理件、电子件、总成件等

## 五、推荐物料阶段拆分方式

### 单工厂场景

可以简化为：

- 原材料
- 在制件（可选）
- 成品件

### 多工厂场景

建议拆成：

- 原材料
- 毛坯件
- 铸造件/锻造件
- 机加件
- 热表后件
- 部件/模块件
- 总装件
- 试验/试车放行件

## 六、推荐工艺工序类型使用方式

### 厂内加工

使用：

- `加工`
- `检验`

### 工厂内不同车间或中心流转

默认不单独建 `厂内转工` 工序，优先并入前后 `加工` / `检验` 节点表达。

### 工厂与工厂之间流转

默认不单独建 `厂际转工` 工序；若存在一级协同计划，则通过 `生产项目部 + 一级工艺 + 协同排产中心 + 一级生产订单` 体现。

### 委外给供应商

使用：

- `外委`

## 七、每次生成都要补齐的底线

无论单工厂还是多工厂，以下内容不能缺：

- 行政组织
- 业务组织
- 用户
- 设备
- 工装工具
- 工装检定策略关系
- 工装保养策略关系
- 工作中心
- 物料
- MBOM / MBOM节点
- 工艺路线
- 工艺路线工序
- 工艺路线工序序列
- 工艺路线工序物料
- 工艺路线工步

## 八、推荐输出风格

### 如果用户只说“帮我生成某产品数据”

默认输出：

- 一套中文种子 JSON
- 一套导出的 Excel
- 一段简短说明：当前采用的是单工厂还是多工厂模式

### 如果用户强调真实业务协同

默认增强：

- 增加多工厂组织
- 增加公司到班组的组织层级
- 增加常见业务角色和真实风格脱敏人员
- 增加更细的设备、工作中心和库房配置
- 按需增加一级工艺、生产项目部和协同排产中心
- 增加供应商和外委工序
- 增加阶段件和半成品
- 增加更完整、更专业的工艺路线和工步

### 如果用户强调只看某个工厂

默认收敛：

- 采用单工厂模式
- 聚焦该工厂内部资源和工艺
- 只保留必要外协，不强行扩成多工厂
