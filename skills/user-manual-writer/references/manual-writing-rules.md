# 用户操作手册编写规则

## 目标

把需求、设计、现有知识页和界面材料整理成可直接阅读、可直接操作、可用于交付培训的用户操作手册。

## 推荐结构

### 模块正文

适合模块或页面级手册：

- `## 功能概述`
- `## 操作前置条件`
- `## 核心功能`
- `## 操作指南`
- `## 注意事项`

### 首页或总览页

适合目录首页、培训导航页、模块地图页：

- 页面用途
- 推荐阅读路径
- 角色分流
- 目录结构
- 关键入口

## 编写口径

- 多写用户动作，少写设计背景
- 菜单路径用统一格式表达，例如：`质量管理 > 检验任务管理`
- 对字段、按钮、标签页、状态名保持与系统页面一致
- 对尚未确认的界面细节，不要编造
- 涉及图片时，优先引用真实图片；没有真实图片时只写补图建议

## 常见落地场景

- 从需求页改写成面向用户的功能说明
- 从测试知识页改写成面向实施或培训的操作说明
- 给现有手册补“前置条件”“注意事项”“操作结果”
- 将讲稿或视频脚本整理成正式手册正文
