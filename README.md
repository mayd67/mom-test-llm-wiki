# MOM LLM Wiki 测试知识库工程

这是一个围绕 MOM 3.0 产品资料、HX 项目测试资料和测试交付流程构建的本地 LLM Wiki 工程。

它的目标不是单纯存放文档，而是把需求、设计、数据模型、操作手册、项目资料、测试经验和测试交付物，整理成一套可检索、可追溯、可复用的知识库，并支撑后续的测试点、测试用例、测试数据、缺陷单和培训手册生成。

## 当前定位

当前仓库同时承担 5 类职责：

- `raw/`：原始资料层，保存需求、项目、产品、接口、测试和截图等来源文件
- `wiki/`：结构化知识层，保存按测试视角整理后的知识页、总览页和专题页
- `outputs/`：测试交付物层，保存需求评审、测试点、测试用例、测试执行、用户手册和测试数据等实际产出
- `scripts/`：辅助治理层，保存批量整理、镜像构建、覆盖检查和历史同步脚本
- `skills/`：仓库级能力层，保存可复用的 Codex skill、路由规则和 agent 元数据

从当前知识库实际内容看，这个仓库已经不是“通用测试资料库”雏形，而是一套围绕 MOM 产品测试工作的 LLM Wiki。

## 当前 Wiki 主结构

当前 `wiki/` 以三个主入口组织内容：

- `01_MOM产品相关文档/`
- `02_HX项目资料/`
- `03_QD项目资料/`

其中 `01_MOM产品相关文档/` 是当前主知识入口，已形成如下结构：

- `00_方法规范/`：知识库分层规则、测试点生成与评审流程、测试用例生成与评审流程、检查清单、使用指南
- `01_产品需求文档/`：标准功能、MOM-AI、优化需求等需求整理页
- `02_数据模型/`：数据模型总览、核心数据模型地图、模块设计地图、原始设计导航和专题整理页
- `03_测试点/`：测试点模板、测试分析资料和 skill 入口页
- `04_测试用例/`：测试用例样例、导入模板说明和 skill 入口页
- `05_产品操作手册/`：快速入门、部署运维、产品平台、核心模块、统计分析、数据模型、开发指南、智能应用、常见问题
- `06_测试数据/`：测试数据说明页和 skill 入口页
- `07_缺陷管理/`：缺陷管理说明页和 skill 入口页

`02_HX项目资料/` 当前主要承载 BJHX/HX 项目的测试总览、环境与风险关注点，以及重点需求测试分析页。

`03_QD项目资料/` 当前专门承载天府轻动 QD 项目的测试总览、模块与集成测试关注点，以及对应原始资料目录。

## raw / wiki / outputs 的关系

- `outputs/` 回答“这次需求或项目实际产出了什么”

## 推荐工作流

### 1. 从需求到测试用例

```text
wiki/01_产品需求文档
-> wiki/02_数据模型
-> outputs/02_测试点/01_待评审
-> outputs/02_测试点/02_已评审
-> outputs/03_测试用例
```

### 2. 从场景到测试数据

```text
wiki/02_数据模型
-> wiki/06_测试数据
-> 测试数据 skill
-> outputs/06_测试数据
```

### 3. 从问题记录到 Jira 缺陷单

```text
原始问题描述/截图摘要/日志摘要
-> wiki/07_缺陷管理
-> 缺陷单 skill
-> outputs/04_测试执行
```

## 维护原则

- 不直接把结论写回 `raw/`
- `wiki/` 只保存结构化、可复用、可检索的知识内容
- `outputs/` 保存当前版本、当前需求、当前项目的交付物
- 所有重要结论都应能追溯到 `raw/`、`wiki/` 主题页或历史交付物
- 新增目录、总览页、skill 或关键专题时，应同步更新 `wiki/index.md` 和 `wiki/log.md`
- 如果顶层结构或主要流程发生变化，应同步更新 `README.md` 和 `SCHEMA.md`

## 关于脚本的说明

仓库中保留了多类历史维护脚本，例如：

- 原始资料复制/镜像构建
- 需求 Wiki 构建
- 数据字典整理
- 测试用例 Wiki 整理
- 覆盖情况检查
- 统一入库入口：`scripts/raw_to_wiki_ingest.py`

其中 `scripts/raw_to_wiki_ingest.py` 用于给 `raw/ -> wiki/` 提供统一入口：

- 会先识别当前仓库是旧版 `legacy` 结构，还是 `team-template` 新结构
- 在 `legacy` 模式下会写入 `99_原始资料`、`99_原始资料镜像`、`10_自动入库镜像` 等受控目录
- 在 `team-template` 模式下才会路由到现有 `build_*` 脚本并同步 wiki 元数据

这些脚本适合用于辅助治理，但执行前应先确认它们输出的目录模型与当前知识库实际结构一致。

特别是涉及 `wiki/index.md` 和 `wiki/log.md` 的同步脚本，当前应先核对输出结果，再决定是否覆盖现有手工维护的导航页。

## 适用场景

这个工程适合以下工作场景：

- 面向 MOM 3.0 产品做需求分析与测试分析
- 基于产品资料、设计文档和手册沉淀长期知识库
- 结合 LLM 从需求持续生成测试点、测试用例和评审产物
- 生成 MOM 场景测试数据和 Jira 缺陷导入文件
- 输出面向实施、测试、交付和培训的用户操作手册
- 作为本地私有化 LLM 的测试知识底座
