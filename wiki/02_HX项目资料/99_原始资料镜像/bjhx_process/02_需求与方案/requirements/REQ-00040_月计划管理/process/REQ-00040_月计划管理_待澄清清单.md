### 二、待澄清问题明细

#### 问题1：指定完成时间的校验粒度

| 维度 | 内容 |
|------|------|
| **问题描述** | 未废弃月计划按SAP订单号+工艺阶段+指定完成时间做唯一校验，但原始需求未明确"指定完成时间"的校验粒度。 |
| **涉及场景** | 月计划生成时的唯一性校验；月计划拆分新增记录的时间填写与校验 |
| **建议澄清方向** | 明确校验粒度：按天（yyyy-MM-dd）即可，还是按所属月份（yyyy-MM），或需精确到时分秒（yyyy-MM-dd HH:mm:ss）？ |
| **影响范围** | 唯一校验算法、拆分界面时间控件精度、数据库字段设计 |

---

#### 问题2：生产订单调整后的重复生成问题

| 维度 | 内容 |
|------|------|
| **问题描述** | 若生产订单A001已生成对应的月计划且未废弃，后续A001调整了指定完成时间，是否会再次生成一份月计划？是否会导致业务冲突？     发布后不允许调整 |
| **涉及场景** | 生产订单信息变更后的月计划同步；月计划唯一校验的业务含义 |
| **建议澄清方向** | 明确同一生产订单是否允许生成多个月计划；若生产订单指定完成时间变更，是更新现有月计划还是生成新计划？原月计划是否需要废弃？ |
| **影响范围** | 月计划生成逻辑、生产订单变更监听机制、历史数据一致性 |

---

#### 问题3：初始界面与调整界面的定义和关系

| 维度 | 内容 |
|------|------|
| **问题描述** | 原始需求多次提及"初始界面"和"调整界面"，但未明确二者的定义、数据范围差异及导航关系。 |
| **涉及场景** | 月计划状态为待提交/驳回/撤回/流程中时，在初始界面处理；已通过月计划在调整界面处理 |
| **建议澄清方向** | 明确是同一页面的不同视图（如Tab切换）还是完全独立的页面；两个界面的数据过滤条件、操作权限、入口导航方式 |
| **影响范围** | 前端页面设计、权限控制、路由设计 |

---

#### 问题4：已废弃数据的显示规则

| 维度 | 内容 |
|------|------|
| **问题描述** | 原始需求未明确已废弃的月计划在初始界面和调整界面中是否需要显示，以及如何显示。 |
| **涉及场景** | 用户在初始界面查询历史月计划；生产订单穿透查看关联月计划（含废弃数据） |
| **建议澄清方向** | 明确已废弃数据是否默认过滤；是否支持按条件查询已废弃数据；废弃数据在穿透查询中是否可见 |
| **影响范围** | 列表查询逻辑、默认过滤条件、数据权限设计 |

---

#### 问题5：月计划拆分的层级限制

| 维度 | 内容 |
|------|------|
| **问题描述** | 原始需求未明确月计划拆分是否支持嵌套拆分，即A拆出A01/A02后，A01/A02是否可继续拆分。 |
| **涉及场景** | 月计划拆分功能的使用边界；多级拆分后的唯一校验逻辑 |
| **建议澄清方向** | 明确是否允许嵌套拆分；若允许，最大拆分层级是多少；嵌套拆分后的父子关系如何维护 |
| **影响范围** | 拆分功能设计、数据模型（父子关系字段）、唯一校验逻辑 |

---

#### 问题6：已通过状态的月计划是否允许拆分

| 维度 | 内容 |
|------|------|
| **问题描述** | 原始需求中"已通过"状态在初始界面显示为只读，但调整界面允许调整。未明确已通过数据是否支持拆分。 |
| **涉及场景** | 已通过月计划的后续分解需求；拆分后的流程走向 |
| **建议澄清方向** | 明确已通过月计划是否可在调整界面拆分；若允许拆分，拆分后的新增记录状态如何标记（待提交/已通过？） |
| **影响范围** | 调整界面功能设计、拆分后状态流转规则 |

---

#### 问题7：月度计划的日期边界定义

| 维度 | 内容 |
|------|------|
| **问题描述** | 原始需求批注中提到"04-26到05-25算4月份计划还是5月份"，说明月度归属规则尚未明确。 |
| **涉及场景** | 月计划生成时的月份归属；帆软报表按月度统计时的数据归集 |
| **建议澄清方向** | 明确月份归属规则：按自然月（1-31日）还是按企业自定义月度周期（如上月26日至本月25日） |
| **影响范围** | 月计划生成逻辑、报表统计维度、月度计划查询条件 |

---

#### 问题8：调整拆分后的数据回流规则

| 维度 | 内容 |
|------|------|
| **问题描述** | 原始需求批注提示"调整拆分后会在初始界面显示"，但未明确回流后的状态标记和数据展示规则。 |
| **涉及场景** | 在调整界面对已通过月计划进行拆分，拆分后的新增记录如何在初始界面呈现 |
| **建议澄清方向** | 明确调整界面拆分后的新增记录是否以"待提交"状态回流到初始界面；原已通过记录是否保持不变 |
| **影响范围** | 调整界面与初始界面的数据同步机制、状态标记规则 |
