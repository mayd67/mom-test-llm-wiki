### 1. 概述

#### 1.1 原始需求

MOM 系统需在制造订单完工后，将完工信息通过 WebService 接口推送至 SAP。该需求覆盖自动推送与手动推送两类场景，其中自动推送用于制造订单关联工序全部完成后的及时上报，手动推送用于接口失败后的人工补发。推送过程中需校验接口必填字段、控制累计推送数量不得超过生产订单计划数量，并记录推送结果供业务查看和异常排查。

### 2. 需求描述

#### 2.1 业务描述

本需求位于 MOM 完工报工与 SAP 完工信息集成之间的业务链路中。业务上，MOM 在车间级执行制造订单及工序报工，而 SAP 侧按生产订单维度接收完工信息。由于一个生产订单可能对应多次、多张制造订单的完工上报，因此本需求需要在每次制造订单满足推送条件时，按本次完工数量向 SAP 推送，同时保证累计成功推送数量不超过生产订单计划数量。

本需求涉及的核心对象关系如下：

`(交付计划)生产订单` `--通过一级工艺展开-->` `(加工计划)生产订单` `--通过释放-->` `制造订单`

其中：

- 生产处接收的是计划类型为“零部件交付计划”的生产订单。
- 零部件交付计划生产订单通过一级工艺展开，生成总装、电装、宏达等分厂级的“零部件加工计划生产订单”。
- 零部件加工计划生产订单通过释放，产生一个或多个制造订单。
- 本需求的自动触发对象是制造订单；接口传值和数量校验的主要来源对象是制造订单所属的零部件加工计划生产订单。

当前原始材料及补充答复明确了以下业务规则：

- 只针对总装、电装、宏达的零部件加工计划。
- 生产处接收计划类型为零部件交付计划的生产订单，再通过一级工艺展开生成各分厂计划类型为零部件加工计划的生产订单。
- 零部件加工计划生产订单通过释放产生一个或多个制造订单，制造订单存储其所属零部件加工计划生产订单 ID。
- 自动推送不直接绑定某个单据操作分支，而是依赖产品层提供的“制造订单完工 WebHook 事件”；二开订阅该事件后自动触发。
- 接口失败后，不自动重试，而是在制造订单管理界面提供人工“推送SAP”入口重新发起。
- 手动推送入口基于产品标准扩展按钮能力实现，权限能力由产品标准支持。
- 手动推送不限制业务场景，但后端需要做重复发送校验。
- 推送前需要校验接口必填字段；若缺失，应明确提示是哪个字段为空导致无法推送。
- 推送前需要根据“已推送SAP数量 + 本次待推送数量 <= 生产订单计划数量”进行数量校验。

#### 2.3 功能描述

##### 2.3.1 自动推送 SAP

- 功能目标：在制造订单满足完工条件后自动将本次完工信息推送至 SAP。
- 适用角色：系统自动执行。
- 前置条件：产品层已提供制造订单完工 WebHook；制造订单满足自动触发条件；接口必填字段可取到；数量校验通过。
- 触发方式/操作步骤：二开订阅制造订单完工 WebHook 事件，收到事件后自动触发推送判断与接口发送。
- 系统处理逻辑：
  1. 判断制造订单是否属于零部件加工计划。
  2. 判断完工事件对应制造订单是否满足业务完工条件。
  3. 组装接口必填字段与请求报文。
  4. 计算本次待推送数量：`本次待推送数量 = 合格数量 + 不合格数量`。
  5. 校验“制造订单所属零部件加工计划生产订单”的 `已推送SAP数量 + 本次待推送数量` 是否大于其计划数量。
  6. 若大于计划数量，则不调用 SAP 接口，记录失败日志并结束。
  7. 若不大于计划数量，则调用 `ZWS_PP_JY` WebService 接口。
  8. 判断返回值 `MTYPE` 是否为 `S`。
  9. 若为 `S`，则更新生产订单已推送SAP数量，并同步更新制造订单已推送SAP数量。
  10. 若不为 `S`，则不更新已推送数量，记录失败日志。
- 输出结果：推送成功或失败结果；相关日志；已推送数量字段更新结果。
- 异常处理/边界处理：必填字段缺失、数量超限、接口返回失败时均不视为成功推送。
- 涉及页面/入口：无界面改动。
- 原型链接/原型说明：无。
- 补充说明：单个报工和批量报工不需要分别定义独立触发逻辑，统一以制造订单完工 WebHook 事件为准。

##### 2.3.2 手动推送 SAP

- 功能目标：对自动推送失败或业务需要重新发送的制造订单，支持人工再次发起推送。
- 适用角色：制造订单管理人员。
- 前置条件：用户进入制造订单管理界面并选中制造订单。
- 触发方式/操作步骤：在制造订单管理界面点击“推送SAP”按钮。
- 系统处理逻辑：
  1. 页面提供“推送SAP”入口。
  2. 当前沟通口径为只支持单选制造订单。
  3. 用户发起后，系统重新取该制造订单相关数据，并按自动推送相同规则执行判空、数量校验、接口调用和结果处理。
  4. 记录本次手动推送结果日志。
- 输出结果：返回本次手动推送成功或失败结果。
- 异常处理/边界处理：前端不限制场景，但后端必须校验同一制造订单不可重复发送。
- 涉及页面/入口：制造订单管理界面。
- 原型链接/原型说明：当前无原型，需后续补充按钮位置、可见性和结果反馈方式。
- 补充说明：手动推送按钮基于产品标准扩展按钮能力实现，权限能力由产品标准支持。

##### 2.3.3 推送前校验

- 功能目标：确保发送给 SAP 的数据完整、数量合法。
- 适用角色：系统自动执行。
- 前置条件：触发自动推送或手动推送。
- 触发方式/操作步骤：接口调用前自动执行。
- 系统处理逻辑：
  1. 按 Excel 字段表识别当前必填字段。
  2. 对每个必填字段进行非空校验。
  3. 若有缺失，则阻止发送，并提示具体缺失字段。
  4. 计算本次待推送数量。
  5. 校验累计成功推送数量与生产订单计划数量关系。
- 输出结果：通过校验则允许发送；不通过则返回明确原因。
- 异常处理/边界处理：若拼音字段等源数据未维护，则视为校验失败并阻止接口发送，同时提示具体原因；不阻断报工主流程。
- 涉及页面/入口：自动推送无页面；手动推送需在界面反馈失败原因。
- 原型链接/原型说明：无。
- 补充说明：除 Excel 标记的必填字段外，其余字段按空字符串传递。

##### 2.3.4 已推送SAP数量字段展示与更新

- 功能目标：为业务提供推送进度查看依据，并支撑零部件加工计划生产订单维度的数量校验与制造订单维度的防重复控制。
- 适用角色：业务用户、系统自动执行。
- 前置条件：完成字段扩展。
- 触发方式/操作步骤：成功推送后更新；业务页面展示。
- 系统处理逻辑：
  1. 在零部件加工计划生产订单和制造订单增加“已推送ERP数量”扩展属性。
  2. 推送成功后，将原值为空按 `0` 处理，并累加本次待推送数量。
  3. 推送失败时不更新该字段。
  4. 页面展示字段供业务查看“有没有发、发了多少”。
- 输出结果：字段值可被查看、用于校验。
- 异常处理/边界处理：字段更新仅在接口成功后执行，失败时不更新。
- 涉及页面/入口：零部件加工计划生产订单、制造订单相关页面；页面显示和查询筛选能力由产品标准功能支持。
- 原型链接/原型说明：无。
- 补充说明：零部件加工计划生产订单和制造订单均需增加扩展属性“已推送ERP数量”；其中零部件加工计划生产订单字段表示该加工计划生产订单累计成功推送到 ERP 的数量，用于与其计划数量做比较校验；制造订单字段表示该制造订单累计成功推送到 ERP 的数量，用于防重复推送并供业务查看。

##### 2.3.5 接口日志记录

- 功能目标：记录每次推送行为及结果，便于排查与人工补发。
- 适用角色：业务用户、实施/运维人员。
- 前置条件：发生自动或手动推送。
- 触发方式/操作步骤：每次推送前后自动记录。
- 系统处理逻辑：
  1. 对校验失败场景记录失败日志。
  2. 对接口调用失败场景记录失败日志、返回消息和原始返回报文。
  3. 对接口调用成功场景记录成功日志和关键业务字段。
- 输出结果：形成可追溯日志。
- 异常处理/边界处理：当前不要求自动重试，仅要求日志可查询。
- 涉及页面/入口：结构化集成日志能力由产品统一建设，本需求对接其记录能力。
- 原型链接/原型说明：无。
- 补充说明：日志至少记录制造订单号、制造订单 ID、本次汇报数量、ERP订单号（取制造订单所属零部件加工计划生产订单的 `intergrationId`）、接口返回结果。

#### 2.4 数据描述

本需求的数据主链路基于 MES 标准模型展开，核心关系为：

`ProdOrder(零部件交付计划生产订单)` `--通过 ProdOrderPrExpandLink -->` `ProdOrder(零部件加工计划生产订单)` `--通过 ProdOrderReleaseLink -->` `ManuOrder`

在执行层面，`ManuOrder` 继续关联 `ManuTask`、`ReportProof`、`InspectTask` 等模型，用于支撑制造订单完工判断、报工取值、检验状态判断及接口推送取值。

本节如未特别说明，涉及接口主取值、数量校验、已推送数量累计等描述时，`ProdOrder` 默认指零部件加工计划生产订单对应对象。

按当前数据模型资料的使用口径，本节将内容区分为三层：

- `2.4.2` 说明本需求引用的产品标准模型。
- `2.4.3` 说明本需求引用的项目扩展模型或扩展属性。
- `2.4.4` 说明本次需求新增或变更的属性、模型或关系。

#### 2.5 性能要求

当前原始材料未给出明确性能指标，结合需求场景暂记录如下，待确认后细化：

- 自动推送应在制造订单满足触发条件后及时发起，不应明显阻塞正常报工流程。
- 手动推送应在用户可接受时间内返回成功或失败结果。
- 批量报工触发多个制造订单推送时，应保证每个制造订单推送结果可独立识别。

#### 2.6 约束

- 本需求仅适用于总装、电装、宏达的零部件加工计划。
- 接口形式为 SAP WebService，当前接口名为 `ZWS_PP_JY`。
- 接口请求字段需符合 Excel 与 WSDL 共同约束，其中部分字段长度存在明确限制，如 `ZJYY` 超过10位需截断。
- 推送数量校验必须以生产订单计划数量为上限。
- 若必填字段缺失，则不得发送接口。
- `MANDT=800` 固定传值。
- 自动推送依赖产品层提供制造订单完工 WebHook 事件。

#### 2.8 实现方案

当前基于原始资料形成的实现方案如下：

1. 产品层提供制造订单完工 WebHook 事件。
2. 二开订阅制造订单完工 WebHook 事件，并在收到事件后基于“制造订单 -> 所属零部件加工计划生产订单”的关系组装接口请求数据。
3. 通过 WebService 方式调用 SAP `ZWS_PP_JY` 接口。
4. 按接口返回结果决定是否更新零部件加工计划生产订单和制造订单上的“已推送SAP数量”字段。
5. 在制造订单管理界面增加“推送SAP”按钮，作为失败后的人工重发入口。
6. 补充零部件加工计划生产订单、制造订单、用户等模型扩展字段，以满足接口取值、去重校验和业务展示要求。
7. 对每次自动/手动推送记录结构化日志，支撑问题排查和补发判断。
