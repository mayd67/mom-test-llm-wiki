# defect-report-generator 使用方法与 Jira 导入步骤

## 适用范围

本说明用于 `defect-report-generator` skill 的日常使用，覆盖两部分内容：

1. 如何把用户提供的问题描述、截图摘要、日志摘要整理成 Jira 可导入 CSV。
2. 如何将生成的 CSV 通过 Jira 的“从 CSV 文件导入问题”功能导入到 `KMMOM-3` 项目。

## 一、skill 使用方法

### 1. 输入材料

支持以下输入方式：

- 单个问题描述
- 多个问题描述批量输入
- 截图说明 + 文字描述
- 报错日志、异常弹窗、SQL 报错摘要
- 已知责任人 / 测试责任人 / 缺陷产生者

### 2. 单条缺陷输入建议

推荐至少包含以下信息：

```text
概要: [页面/模块] 某操作后出现某异常
问题描述: ...
操作步骤:
1. ...
2. ...
实际结果: ...
期望结果: ...
```

如果素材不完整，skill 会按内置规则补齐默认值；待确认项不会写入 Jira `描述` 字段。

### 3. 多条缺陷批量输入建议

一个独立问题对应一条缺陷。多个问题可一次性输入，并生成 **一个 CSV 文件中的多行 bug 单**。

推荐两种写法：

#### 写法 A：按问题编号拆分

```text
问题1：工作台-工序任务报工界面报错
概要: [工序任务报工] 工作台打开界面报错
问题描述: ...
操作步骤:
1. ...
实际结果: ...
期望结果: ...

问题2：物料管理界面打开显示空白
概要: [物料管理] 物料管理界面打开显示空白
问题描述: ...
操作步骤:
1. ...
实际结果: ...
期望结果: ...
```

#### 写法 B：按分隔线拆分

```text
概要: [模块A] 问题A
问题描述: ...
操作步骤:
1. ...
实际结果: ...
期望结果: ...
---
概要: [模块B] 问题B
问题描述: ...
操作步骤:
1. ...
实际结果: ...
期望结果: ...
```

识别规则如下：

- 出现 `问题1：...`、`缺陷2：...`、`bug3: ...`、`issue4: ...` 时，按多条缺陷处理。
- 出现 `---`、`===`、`***` 分隔线时，按多条缺陷处理。
- 没有明确分隔标记时，默认按单条缺陷处理。

### 4. 责任字段补充规则

如果已知以下字段，建议一并提供：

- `责任人`
- `测试责任人`
- `缺陷产生者`

支持两种提供方式：

- 直接给 Jira 账号，例如 `xueqk`、`mayd`
- 给中文姓名，由 skill 转换为 Jira 账号，例如：
  - `薛启宽 -> xueqk`
  - `马雨逗 -> mayd`

### 5. skill 输出结果

skill 默认直接生成 Jira 导入 CSV，不需要额外确认是否落文件。

默认输出目录：

- `defect-report-generator/exports/`

默认文件名格式：

- `jira_import_(MM-DD-NNN).csv`

例如：

- `jira_import_(03-27-010).csv`

同时通常会保留一份原始整理笔记：

- `defect-report-generator/raw_notes_xxx.txt`

## 二、导入 Jira 步骤

以下步骤按当前 KMMOM Jira 页面实际操作整理。

### 步骤 1：进入 CSV 导入入口

在 Jira 顶部菜单执行：

- `问题`
- `从CSV文件导入问题`

### 步骤 2：上传 skill 生成的 CSV 文件

在“批量创建 设置”页面：

1. 选择 CSV 文件，上传 skill 生成的文件，例如：
   - `jira_import_(03-27-010).csv`
2. 勾选：
   - `使用现有的配置文件`
3. 选择配置文件：
   - `\导入jira配置文件\BulkCreate-configuration-202603251632.txt`
4. 点击：
   - `下一步`

说明：

- 建议优先使用现有配置文件，这样字段映射和对应值映射会自动带出，减少手工操作。

### 步骤 3：设置导入参数

在第二个“设置”页面中，确认以下参数：

- 导入到项目：`KMMOM-3`
- 文件编码：`UTF-8`
- 分隔符：`,`
- 日期格式：`yyyy/MM/dd`

确认无误后点击：

- `下一步`

### 步骤 4：确认字段映射

进入“对应域”页面后，检查 CSV 字段与 Jira 字段的映射关系。

使用现有配置文件时，通常会自动带出映射。根据当前导入页面，重点检查以下字段：

- `问题类型 -> 问题类型`
- `概要 -> 概要`
- `模块 -> 模块`
- `描述 -> 描述`
- `影响范围分析 -> 影响范围分析`
- `责任人 -> 责任人`
- `测试责任人 -> 测试责任人`
- `缺陷产生者 -> 缺陷产生者`
- `缺陷严重程度 -> 缺陷严重程度`
- `对用户的影响程度 -> 对用户的影响程度`
- `到期日 -> 到期日`
- `使用的版本 -> 使用的版本`
- `修复的版本 -> 修复的版本`

按当前截图，`状态` 字段页面上显示为：

- `状态 -> 不要对应此域`

如果页面已自动带出上述映射，直接点击：

- `下一步`

### 步骤 5：确认对应值并开始导入

进入“对应值”页面后：

1. 如页面无额外异常提示，点击：
   - `开始导入`
2. 等待 Jira 执行导入。

### 步骤 6：检查导入结果

导入完成后，建议检查：

- 是否成功创建了对应数量的问题单
- `概要`、`模块`、`优先级`、`缺陷严重程度` 是否正确
- `责任人`、`测试责任人`、`缺陷产生者` 是否正确
- `描述` 与 `影响范围分析` 是否完整
- `到期日`、`使用的版本`、`修复的版本` 是否正常

## 三、推荐使用流程

推荐日常按以下顺序执行：

1. 收集问题描述 / 截图 / 报错信息。
2. 使用 `defect-report-generator` 生成 CSV。
3. 如责任字段已知，生成时一并补齐。
4. 打开 Jira，进入 `问题 -> 从CSV文件导入问题`。
5. 上传 CSV，并使用现有配置文件。
6. 确认项目、编码、分隔符、日期格式。
7. 检查字段映射。
8. 点击 `开始导入`。

## 四、常见注意事项

### 1. CSV 文件名不要手改业务名

建议保留脚本默认生成的文件名格式：

- `jira_import_(MM-DD-NNN).csv`

### 2. 日期格式必须与 Jira 设置一致

当前导入页面使用：

- `yyyy/MM/dd`

如果手工改动 CSV 日期格式，可能导致导入失败或日期解析异常。

### 3. 多问题导入要有明确分隔

如果一次输入多个问题，请使用：

- `问题1：...` / `问题2：...`
- 或 `---` 分隔线

否则可能被识别为一条缺陷。

### 4. 截图不能自动成为 Jira 附件

skill 可以根据截图内容整理缺陷描述，但生成的 CSV 不会自动上传截图附件。

如果需要在 Jira 中保留截图证据，请在导入后手工补充附件，或在原始素材中记录附件地址。

### 5. 使用现有配置文件优先

建议持续使用以下配置文件：

- `D:\06_AI协同工作\01_MOM3.0产品\07_缺陷生成\导入jira配置文件\BulkCreate-configuration-202603251632.txt`

这样可以保持字段映射一致，减少手工调整。
