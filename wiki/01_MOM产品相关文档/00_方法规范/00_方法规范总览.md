# 方法规范总览

本目录用于集中存放测试知识库中的方法、流程、规则和检查清单。

它和业务资料目录的关系是：

- `01_产品需求文档/`：放需求内容
- `02_数据模型/`：放设计与数据模型资料
- `03_测试点/`：放测试点模板、skill 入口、样例资源
- `04_测试用例/`：放测试用例模板、样例、导入模板、skill 入口
- `00_方法规范/`：放测试工作方法、知识库规则、评审清单
- `skills/`：放可复用 skill 本体、参考资料和 agent 元数据

一句话理解：

- 前四个目录回答“资料是什么”
- `00_方法规范/` 回答“资料应该怎么用”

## 二、目录文件说明

### 1. [[raw与wiki分层规则]]

作用：

- 定义 `raw/`、`wiki/`、`outputs/` 三层边界
- 明确哪些资料必须整理进 `wiki`
- 明确哪些资料只需要索引，不必全文清洗

适用场景：

- 新资料入库
- 判断原始资料是否需要迁入 wiki
- 判断测试点和测试用例应该引用哪里

### 2. [[测试点生成与评审流程]]

作用：

- 规范从需求到测试点的生成流程
- 规范测试点评审和版本流转方式

适用场景：

- 新需求测试分析
- 测试点初稿编写
- 测试点从待评审转已评审

### 3. [[测试点评审检查清单]]

作用：

- 提供评审测试点时的统一检查项
- 固定评审依据和关注重点

适用场景：

- 组内评审
- 自检
- 发现漏项、口径偏差、联动缺失时定位问题来源

### 4. [[测试用例生成与评审流程]]

作用：

- 规范从已评审测试点到测试用例的生成流程
- 规范 MeterSphere 输出口径
- 规范测试用例评审重点

适用场景：

- 测试用例初稿生成
- 测试用例导入前检查
- 测试用例评审

### 5. `skills/raw-to-wiki-ingest/`

作用：

- 统一 `raw/ -> wiki/` 自动入库入口
- 先识别当前仓库属于 `legacy` 还是 `team-template`
- 在 `legacy` 结构下只写安全镜像页，不覆盖人工整理页

适用场景：

- 新资料批量入库
- 增量监听 `raw/`
- 为后续测试分析准备统一的镜像入口

### 6. [[测试交付物目录规范]]

作用：

- 统一测试点、测试用例、测试数据、测试执行和用户手册等产物在 `outputs/` 中的落位规则
- 统一评审态、导入态、已沉淀态和归档态的目录口径

适用场景：

- 判断新产物应放到哪个目录
- 清理 `outputs/` 根目录散落文件
- 规范测试用例导入版和正文版的分目录保存方式

### 7. `skills/test-output-placement/`

作用：

- 让 AI 在生成或整理交付物时，按统一目录规则判断目标路径
- 同时给出建议文件名和放置理由

适用场景：

- 让 Codex 判断“这个文件应该放哪”
- 批量整理历史产物
- 检查某个文件应进入 `raw/`、`wiki/` 还是 `outputs/`

## 三、当前工作方式

当前项目已经形成的标准路径是：

```text
wiki中的需求文档
-> wiki中的设计与数据模型资料
-> 生成测试点
-> 测试点评审
-> 生成测试用例
-> 测试用例评审
-> 导入 MeterSphere
```

其中：

- 需求、设计、数据模型主要从 `wiki` 中读取
- 具体交付物保存在 `outputs/`
- 方法和规范保存在 `00_方法规范/`
