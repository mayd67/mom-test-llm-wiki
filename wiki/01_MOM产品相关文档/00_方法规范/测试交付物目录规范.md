# 测试交付物目录规范

本规范用于回答一个问题：

- 测试工作中生成的文件，应该放到 `outputs/` 的哪个目录

它和 `raw/`、`wiki/` 的边界关系是：

- `raw/` 放原始输入资料
- `wiki/` 放长期知识、方法、模板和 skill
- `outputs/` 放当前需求、当前项目、当前阶段的实际交付物

## 一、一级目录规则

当前 `outputs/` 一级目录按交付物类型划分：

- `01_需求评审/`：需求评审问题、澄清记录、可测性分析、风险清单
- `02_测试点/`：测试点初稿、已评审测试点、已沉淀测试点
- `03_测试用例/`：测试用例工作稿、评审稿、导入版和标准样例
- `04_测试执行/`：测试计划、执行记录、缺陷导出、测试报告、回归验证
- `05_用户操作手册/`：用户手册正文、培训讲稿、操作视频脚本
- `06_测试数据/`：测试数据种子、场景导入包、说明文件
- `99_归档/`：历史版本、旧目录散落产物和废弃交付物

结论很简单：

- 看“产物类型”决定一级目录
- 看“评审状态或交付状态”决定二级目录

## 二、测试点怎么放

测试点固定放在 `outputs/02_测试点/`，再按状态细分：

- `01_待评审/`：初稿，尚未评审
- `02_已评审/`：评审通过，可继续写测试用例
- `03_已沉淀/`：已提炼出稳定规则，但仍保留为交付物

命名建议：

```text
需求编号-需求名称-测试点-V1.0.md
需求编号-需求名称-测试点-YYYYMMDD.md
```

示例：

```text
DNW31500-智能问数-测试点-V1.0.md
```

## 三、测试用例怎么放

测试用例固定放在 `outputs/03_测试用例/`，建议按用途拆分：

- `01_待评审/`：测试用例工作稿、草稿
- `02_已评审/`：评审通过的 Markdown 正文
- `03_MeterSphere导入/`：系统导入版 Excel
- `04_已沉淀/`：通用样例、标准化复用版本

命名建议：

```text
需求编号-模块名称-测试用例-V1.0.md
需求编号-模块名称-测试用例-MeterSphere导入-V1.0.xlsx
```

示例：

```text
REQ-00010-火鸡品管理-测试用例-V1.0.md
REQ-00010-火鸡品管理-测试用例-MeterSphere导入-V1.0.xlsx
```

判断规则：

- 如果主要给人评审和阅读，用 Markdown
- 如果主要给 MeterSphere 导入，用 Excel
- 两者同时存在时，分目录存放，不混在一起

## 四、测试数据怎么放

测试数据固定放在 `outputs/06_测试数据/`，按业务场景建目录：

```text
outputs/06_测试数据/
└── 场景名称/
    ├── *_seed.json
    ├── *_import/
    ├── *_import.zip
    └── 说明文件.md
```

例如：

```text
outputs/06_测试数据/大疆无人机/
```

这里放的是场景数据产物，不是测试数据 skill 本身。skill 本体统一放在根目录 `skills/mom-business-data-generator/`。

## 五、测试执行和用户手册怎么放

测试执行相关文件进入 `outputs/04_测试执行/`：

- 测试计划
- 执行记录
- 缺陷导出文件
- 测试报告
- 回归验证记录

用户手册相关文件进入 `outputs/05_用户操作手册/`：

- 正式操作手册正文
- 培训讲稿
- 录屏视频脚本
- 模块化文档目录

## 六、根目录约束

`outputs/` 根目录只保留：

- README
- 标准编号目录

不应该直接堆放：

- 单个测试点文件
- 单个测试用例文件
- 单个测试数据 zip
- 单个测试报告

如果发现根目录散落文件，应迁移到对应编号目录；如果属于历史遗留且状态不清楚，先归档到 `99_归档/` 或等待确认后再移动。

## 七、命名原则

- 一个文件尽量只对应一个需求、一个模块或一个场景
- 文件名中优先包含需求编号、模块名、交付物类型、版本号或日期
- 避免 `最终版`、`最新版` 这种不可追踪命名

推荐形式：

```text
需求编号-模块名称-交付物类型-V1.0.md
项目名称-场景名称-交付物类型-V1.0.xlsx
```

## 八、配套 skill

如果需要让 AI 直接判断“这个文件应该放哪”，使用：

- `skills/test-output-placement/`

这个 skill 适用于：

- 新产物生成前先判断目录
- 历史产物整理归位
- 检查某个文件应进入 `raw/`、`wiki/` 还是 `outputs/`
- 给导入版文件生成标准命名
