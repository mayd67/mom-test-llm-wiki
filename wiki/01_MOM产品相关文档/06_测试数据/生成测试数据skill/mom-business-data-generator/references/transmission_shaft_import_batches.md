# 传动轴场景导入批次说明

## 一、用途

本说明用于指导“传动轴 / 42CrMo高精度花键传动轴”场景在同一套环境中连续导入多套数据时，如何选择批次、如何避免编码冲突，以及推荐的导入顺序。

## 二、先看结论

如果你要把多套传动轴数据导入同一个环境，优先使用下面这三套：

1. `标准版`：命名空间 `TS20S01`
2. `大体量版`：命名空间 `TS31S01`
3. `超大体量版`：命名空间 `TS42S01`

这三套已经做了唯一命名空间隔离，可以直接共存在同一环境中，不需要再额外准备 `ns31`、`ns42` 之类的别名版本。

## 三、推荐导入批次

### 批次 1：标准版

- 命名空间：`TS20S01`
- 种子文件：`assets/transmission_shaft_seed.json`
- 导出目录：`output/transmission_shaft_seed`
- 适用场景：先做基础 POC、先验证模板字段与引用关系、先演示典型机加工单工厂传动轴主线。

### 批次 2：大体量版

- 命名空间：`TS31S01`
- 种子文件：`assets/transmission_shaft_seed_big.json`
- 导出目录：`output/transmission_shaft_seed_big`
- 适用场景：在标准版导入成功后，继续展示更多操作工、更多并行设备与工作中心、更多工艺与备料数据。

### 批次 3：超大体量版

- 命名空间：`TS42S01`
- 种子文件：`assets/transmission_shaft_seed_ultra.json`
- 导出目录：`output/transmission_shaft_seed_ultra`
- 适用场景：进一步展示高体量自动生成能力，突出单工厂机加工场景下的用户、设备、工作中心、物料与工艺扩容效果。

## 四、每一批内部的推荐导入顺序

每一套数据内部，建议按以下顺序导入：

1. `系统配置_模板.xlsx`
2. `工厂资源_模板.xlsx`
3. `产品与工艺_模板.xlsx`
4. `生产订单_模板.xlsx`

原因：

- 先导入组织与用户，后续发布人和组织引用才有落点。
- 先导入设备、工作中心、供应商，后续工艺与资源引用才能成立。
- 先导入物料、MBOM、工艺路线，再导入生产订单和备料清单更稳妥。

## 五、推荐的同环境连续导入顺序

如果你要在一套环境里逐步扩容演示，推荐顺序如下：

1. 先导入 `output/transmission_shaft_seed`
2. 再导入 `output/transmission_shaft_seed_big`
3. 最后导入 `output/transmission_shaft_seed_ultra`

这样可以先用标准版验证环境与模板，再逐步展示同一业务模型下的大体量与超大体量扩容效果。

## 七、导入时的注意事项

- 三套版本都采用唯一命名空间，可用于同环境连续导入。
- 场景主线统一为“下料 → 粗半精车 → 外协热处理 → 精磨 → 清洗防锈 → 终检 → 包装入库”。
- 当前场景保留 `1` 条 `工作中心与供应商的关系`，用于体现外协热处理。
- 当前场景无 `厂际转工`，仅保留 `外委` 和 `厂内转工`。
- 模板当前对 `物料`、`MBOM节点`、`生产订单` 的计量单位口径实际约束为 `个`，三套版本均已按该口径处理。
- `工艺路线工序序列` 默认采用 `ES`；`工艺路线` sheet 的 `发布人` 留空；`工装工具`、`物料`、`MBOM` 的 `发布人` 已按用户编号引用。
- 导出时如果用户、设备或工作中心关系行数超过模板预留，会出现结构警告，但当前三套版本均已完成校验与 Excel 导出。
