# QD项目测试总览

本文档是 QD 项目资料进入测试知识库后的总入口，目标是帮助测试工程师快速回答三个问题：

1. 天府轻动 QD 项目当前要交付哪些制造运营能力
2. 哪些业务链路最值得优先组织测试
3. 现有资料已经明确了什么，哪些内容还需要继续补资料

## 一、项目定位

- 项目对象是四川天府轻型动力科技有限公司的 MOM 制造运营管理模块，面向航空发动机研制与制造场景。
- 当前入库资料对应《天府轻动MOM项目详细设计方案V3》，版本演进为 `2025-11-26` 的 `V1`、`2025-12-24` 的 `V2`、`2026-01-09` 的 `V3`。
- 该方案承接“七大核心业务场景”中的制造场景，重点覆盖工艺数据、生产管理、装配试车、质量、仓储配送和决策分析。
- 从测试视角看，这不是单一模块验证，而是一套“计划下达 -> 执行反馈 -> 质量闭环 -> 仓储协同 -> 集成回传”的项目级链路验证。

## 二、本期业务范围

- 工艺数据管理：接收 `MBOM`、工艺路线、图纸文件和相关变更信息，作为生产与质量执行底座。
- 生产管理：接收或导入生产订单，完成拆分、指定工艺、批次编号、排程、进度监控和完工反馈。
- 装配试车执行：围绕装配任务、试车任务、串换件、异常、工时等场景组织现场执行与报工反馈。
- 质量管理：覆盖入库检验、过程检验、故检、不合格品、返工返修、废品处置、计量器具和电子卷宗。
- 仓储与配送：覆盖到货入库、组箱、库存、领料、出库、盘点、库房建模，以及与 `WCS`、`AGV` 的协同。
- 决策分析：通过看板和报表对计划达成、生产执行、异常、质量、库存等数据进行统计展示。

## 三、系统边界与上下游

| 系统 | QD 方案中明确的边界 | 测试含义 |
| --- | --- | --- |
| `PLM` | 下发 `MBOM`、工艺路线、工艺文件、设计/工艺变更及其他技术单据 | 要重点验证版本、对象映射、变更通知和附件可追溯性 |
| `ERP` | 下发生产订单、计划变更、到货/发货通知，接收完工、外委、出入库和盘点结果 | 要重点验证状态映射、回传时机、失败重试和数据一致性 |
| `WCS` | 接收组箱、出库和搬运任务，下发库位和执行结果 | 要重点验证库位回写、任务状态同步和异常补偿 |
| 主数据系统 | 下发组织人员、设备、供应商、物料主数据 | 要重点验证唯一性、权限、版本和历史记录保留 |
| `OA` | 接收审批待办并支持单点登录回到 `MOM` 审批 | 要重点验证待办同步、转办、终止和登录跳转 |
| 应用集成平台 | 统一承接系统间发送与接收 | 要重点验证路由、报错、重复消息和链路监控 |

## 四、当前优先测试主线

- 生产计划与变更链路：订单接收/导入、计划拆分、指定工艺、排程、时间变更、状态变更、工艺变更。
- 装配试车执行链路：任务分派、收料确认、开工、检查项填报、报工、试验问题记录、试后恢复自查。
- 仓储配送协同链路：到货入库、组箱、库位回写、领料申请、出库、盘点、`AGV/WCS` 任务闭环。
- 质量与审批链路：检验任务、不合格品、故检、返工返修、废品、质量异常流程和计量预警。
- 基础数据与追溯链路：物料、`MBOM`、工艺路线、组织人员、设备、电子卷宗、条码和工艺单据。

详细拆解见：[[01_QD项目模块与集成测试关注点]]。

## 五、验收与交付约束

- 方案明确要求各模块功能在实施过程中逐步细化并完善，最终以“用户功能验证并确认签字”为验收依据。
- 验收不仅看功能结果，还包括交付文档移交、系统维护与操作培训效果。
- 文档中列出的 `PLM`、`ERP`、`WCS`、主数据、`OA`、应用集成平台专项集成方案均要求单独评审，说明接口级验证口径不能只靠本页结论替代。
- 方案签字确认后，如发生功能或范围变更，需要走正式变更管理流程；测试留痕应能支撑影响分析和后续回归。
