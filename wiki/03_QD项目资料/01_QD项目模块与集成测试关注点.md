# QD项目模块与集成测试关注点

本页把 QD 详细设计按测试主线重新编排。带“建议”字样的内容，是基于当前详细设计方案推导出的测试关注点，不等同于已单独评审通过的实施细则。

## 一、优先测试矩阵

| 主线 | 代表功能编号 | 关键验证点 |
| --- | --- | --- |
| 生产计划与变更 | `MOM--ERP-01/02/06`、`MOM-JH-01~07`、`MOM-SJBG-01`、`MOM-GYBG-01~03` | 订单接收/导入一致性、计划拆分、指定工艺、批次号唯一、排程下发、时间与状态变更、工艺变更后的补料/退料 |
| 装配试车执行 | `MOM-RW-01~10`、`MOM-CHJ-01~02`、`MOM-YC-01/03/04`、`MOM-GS-01~04` | 任务流转、收料与开工、检查项填报、附件上传、报工反馈、串换件审批、异常闭环、工时准确性 |
| 仓储与配送 | `MOM-RK-01/02`、`MOM-CK-01~03`、`MOM-PD-01~03`、`MOM-KF-01~03`、`MOM--WCS-01/02/04`、`MOM--ERP-08` | 到货入库、组箱、库位回写、领料与出库、盘点差异过账、`WCS/AGV` 任务状态同步 |
| 质量闭环 | `MOM-RKJY-01~03`、`MOM-GCJY-01`、`MOM-GJ-01`、`MOM-BHG-01`、`MOM-FGFX-01`、`MOM-WBFX-01`、`MOM-BF-01`、`MOM-JLQJ-01~03` | 检验任务创建与执行、质量结论驱动后续流程、返工返修与外委返修、废品处置、计量预警和借还记录 |
| 工作流与OA | `MOM-GZL-01~16` | 流程模型发布、待办同步、回退/加签/转办、多人会签、单点登录、流程终止后的业务状态一致性 |
| 基础数据与追溯 | `MOM-JCSJ-01~10` | 物料、`MBOM`、工艺路线、组织人员、工作中心、供应商、设备、电子卷宗、条码、工艺单据的版本、唯一性和追溯性 |

## 二、按主线拆解的测试关注点

### 1. 生产计划与变更

- 生产订单既支持 `ERP` 接收，也支持 `Excel` 导入，测试时要核对两条入口在字段默认值、主键唯一性、状态初始化上的一致性。
- 发动机计划存在“多装多试”拆分为装配、试车、分解子订单的要求，建议把拆分前后主订单、子订单、工艺路线和进度监控放在同一条回归链路里验证。
- 计划变更覆盖暂停、恢复、终止、时间调整、优先级调整、设计变更和工艺变更，建议重点验证“已开工工序如何暂停/继续”和“补料/退料是否正确触发”。
- 文档明确临时试制、返工返修、临时分解、出厂试车计划会通过导入进入系统，建议准备一组非标准订单样本专门覆盖。

### 2. 装配试车执行

- 装配任务管理覆盖任务分派、任务协调、收料确认、开工、检查项填报、浏览工艺文件、报工七个核心动作，建议按一个完整工序任务串起来验。
- 报工场景明确“检验结果为不合格时触发不合格品审批流程”，这意味着报工测试不能只看数量与状态，还要看质量闭环是否真正启动。
- 试车任务管理额外包含试验问题记录和试验后恢复自查，建议重点验证附件上传、问题记录留痕和自查结果对后续状态的影响。
- 串换件、异常、工时三条支线都依赖审批或后续台账，建议验证“页面动作成功”之外，再追一层到审批流、日志和统计结果。

### 3. 仓储、配送与WCS协同

- 入库链路是“接收 `ERP` 到货单 -> 创建入库申请单 -> 组箱 -> 物料入库 -> `WCS` 回写库位信息”，建议把这几步作为一条端到端链路执行。
- 出库链路既有成品发货，也有车间领料与分拣搬运，建议区分 `ERP` 发货通知、`WCS` 分拣任务和 `AGV` 搬运任务三类状态回传。
- 盘点链路包含创建盘点单、实盘录入、差异过账和盘点结果回传 `ERP`，建议重点验证差异数据、重复过账和中断恢复。
- 库房基础管理扩展到库房建模、库存管理和预警管理，建议确认这些能力不会和项目级现场流程冲突，尤其是预警、冻结、特殊物料标签等场景。

### 4. 质量闭环与电子追溯

- 入库检验、过程检验、故检、不合格品、返工返修、废品处置之间存在明确的结果驱动关系，建议按“发现问题 -> 流程审批 -> 处理结论 -> 业务继续/返工/报废”设计闭环用例。
- 故检单、不合格品审理单、废品通知单都强调附件上传与审批流联动，测试时要核对表单字段、附件、审批意见和业务对象状态是否同步。
- 质量问题通知流程包含多人会签、超时标红、调整归零计划等复杂规则，是高风险流程，建议单独准备会签、超时、回退和再提交样本。
- 电子卷宗在现状分析和基础数据管理中都被提到，建议把“过程记录是否最终沉淀为可追溯卷宗”作为专项检查点，而不是只验证单页面保存成功。

### 5. 工作流、权限与OA协同

- 文档列出了 `16` 类业务审批流程，测试时应把“流程模型本身”与“被流程驱动的业务单据”分开验，避免只看流程节点流转而忽略业务状态。
- 待办任务支持审批、驳回、加签、批量审批，且批量审批限制为“同一流程模型 + 同一业务模型”，建议准备正反两类批量样本。
- `OA` 集成不仅是消息推送，还包括转办同步、流程终止同步和单点登录跳转，建议验证待办取消、转派后归属变化和会话跳转是否正确。

### 6. 基础数据与配置底座

- 基础数据管理覆盖物料、`MBOM`、工艺路线、组织人员、工作中心、供应商、设备台账、电子卷宗、条码和工艺单据，建议优先关注唯一性、版本时效、启停状态和权限。
- 该项目大量业务都依赖基础数据先被正确下发，因此建议把主数据检查放到业务冒烟前，避免大量功能缺陷其实是底座数据问题。

## 三、集成测试重点

| 集成对象 | 当前资料已明确 | 当前仍需补充 |
| --- | --- | --- |
| `PLM` | `MBOM`、工艺路线、工艺文件、设计/工艺变更、施工单等由 `WebAPI` 下发 | 字段映射、版本冲突口径、附件传输失败补偿 |
| `ERP` | 生产订单、计划变更、到货/发货通知下发；完工、外委、出入库、盘点结果回传 | 报文样例、重试机制、幂等键、失败回滚 |
| `WCS` | 组箱、出库、搬运任务下发；库位和执行结果回写 | 任务拆分粒度、异常状态码、重发规则 |
| 主数据 | 组织人员、设备、供应商、物料主数据同步 | 增量同步、停用数据处理、历史版本保留 |
| `OA` | 待办同步、转办、终止同步、单点登录 | 会话失效、权限边界、跨系统审计留痕 |
| 集成平台 | 各系统通过统一平台收发 | 路由监控、链路告警、重复消息拦截 |

说明：

- 上表“当前仍需补充”不是缺陷结论，而是因为详细设计文档只给出集成范围和方向，未给出专项集成方案原文。
- 在专项集成方案入库前，建议先从业务链路层验证“数据有没有到、状态有没有变、失败有没有留痕”，再逐步补接口级精细化用例。

## 四、建议留证方式

- 对端到端业务链路，至少保留：源单据编号、目标单据编号、关键状态变化、审批实例号、接口时间点和截图/日志。
- 对集成异常，至少保留：请求方向、对象主键、业务状态、错误提示、重试结果和最终一致性结论。
- 对质量与流程类问题，至少保留：附件、审批意见、处理结论和后续业务对象是否继续流转。
